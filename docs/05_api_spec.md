## 1. 한눈에 보기

### 1.1 API란

화면이 서버에 보내는 요청의 약속이다. "이 주소로 이런 값을 보내면 이런 답이 온다"를 정한다. 화면을 만드는 사람과 서버를 만드는 사람이 이 문서를 기준으로 따로 작업한다.

### 1.2 목록

방식의 GET은 조회, POST는 계산하거나 새로 만들기, PUT은 저장(고치기), DELETE는 지우기다.

- "로그인 필요"인 API는 로그인하지 않은 요청을 서버가 거부한다 (NFR-10).
- 1차 동안에는 로그인 기능이 없다. A-08 ~ A-11은 고정된 테스트 사용자 한 명의 값을 읽고 쓴다 (T-USER-08). 2차에 로그인을 붙여도 주소와 모양은 그대로다.
- 계산과 탐색(A-03 ~ A-07, A-12)은 로그인과 상관없이 쓸 수 있다. 필요한 값을 요청에 담아 보낸다 (NFR-18, FR-USER-20).

### 1.3 가장 중요한 원칙 세 가지

| 원칙 | 내용 | 근거 |
| --- | --- | --- |
| 계산은 서버만 한다. | 화면은 계산하지 않고 서버가 준 숫자를 표시만 한다. 같은 값이 화면마다 다르게 나오는 일을 막는다. | NFR-13 |
| 계산에 쓸 값은 요청에 담는다. | 서버는 DB에 저장된 재무정보를 꺼내 계산하지 않는다. 그래서 로그인하지 않아도 모든 계산이 된다. | NFR-18 |
| 외부 API를 요청 중에 부르지 않는다. | 실거래가와 좌표는 DB에 넣어 둔 것만 쓴다. | NFR-08 |

## 2. 공통 규칙

### 2.1 형식

| 항목 | 규칙 |
| --- | --- |
| 주소 | 모두 `/api`로 시작한다. 영문 소문자와 줄표를 쓴다. |
| 주고받는 형식 | JSON, UTF-8 |
| 이름 | 영문 소문자와 밑줄. DB의 칸 이름과 같게 쓴다. |
| 금액 | **원 단위 정수.** 요청과 응답 모두 같다. 화면이 만원으로 받은 값에 10,000을 곱해 보내고, 받은 값을 만원 단위로 반올림해 보여 준다. (6.1의 Q-1) |
| 비율과 금리 | 대출 비율은 0.700 같은 소수, 금리와 허용 상승률은 4.0 같은 퍼센트 값 |
| 면적 | ㎡. 평으로 바꾸는 일은 화면이 한다 (㎡ ÷ 3.3058). |
| 날짜, 시각 | 날짜는 `2026-10-11`, 시각은 `2026-10-11T21:30:00` |
| 없는 값 | `null`. 좌표, 세대수, 공급면적을 모를 때와, 표시하지 않기로 한 계산 결과에 쓴다. |
| 구분 | `now`(지금 가능), `within`(기간 내 가능), `lack`(자금 부족). DB와 같다. |

### 2.2 조건 묶음 (`conditions`)

계산과 탐색에 쓰는 사용자의 값이다. A-05, A-07, A-12, A-21, A-24가 같은 모양으로 받는다.

```json
{
  "current_assets": 50000000,
  "monthly_saving": 1000000,
  "target_years": 5,
  "loan_choice": "product",
  "loan_product_id": 1,
  "repayment_years": 30
}
```

| 값 | 형식 | 규칙 |
| --- | --- | --- |
| `current_assets` | 정수 | 현재 보유자산(원). 0 ~ 100억 |
| `monthly_saving` | 정수 | 월 저축 가능액(원). 0 ~ 10억 |
| `target_years` | 정수 | 목표 기간. 0, 3, 5, 10 중 하나. 0은 "지금" |
| `loan_choice` | 글자 | `product`(상품을 고름) 또는 `none`(대출 없이 계산) |
| `loan_product_id` | 정수 또는 null | `product`일 때 필수, `none`일 때 null |
| `repayment_years` | 정수 또는 null | `product`일 때 필수이고 그 상품의 선택지 중 하나. `none`일 때 null |

- 하나라도 빠지면 계산하지 않고 오류를 돌려준다. 화면은 빠진 입력 단계로 안내한다 (FR-RESULT-10).
- 나이와 연 소득은 계산에 쓰지 않으므로 넣지 않는다.

### 2.3 로그인

- 로그인 상태는 쿠키로 확인한다. 화면은 요청을 보낼 때 쿠키가 함께 가도록 설정한다. 서명한 쿠키에 회원 번호를 담는다 (아키텍처 문서 8.2).
- 마지막 요청 뒤 30분이 지나면 로그인이 풀린다 (FR-USER-08). 그 뒤 "로그인 필요"인 API를 부르면 401이 온다. 화면은 시작 화면으로 보내고 "30분 동안 사용하지 않아 로그아웃되었습니다"를 보여 준다 (와이어프레임 P-01 ⑤).
- 로그인하지 않은 사용자의 화면은 A-08 ~ A-11, A-29 ~ A-34를 부르지 않는다. 값은 브라우저에만 둔다 (FR-PROFILE-04).

### 2.4 응답 코드

| 코드 | 뜻 | 쓰는 때 |
| --- | --- | --- |
| 200 | 성공 | 조회, 계산, 저장 |
| 201 | 만들어짐 | 회원가입, 결과 저장 |
| 204 | 성공, 돌려줄 내용 없음 | 로그아웃, 탈퇴 |
| 401 | 로그인이 필요하거나 로그인 정보가 틀림 | 로그인하지 않은 요청, 로그인 실패 |
| 404 | 찾는 것이 없음 | 없는 아파트 번호, 없는 저장 결과, 남의 저장 결과 |
| 409 | 이미 있음 | 이미 사용 중인 아이디 |
| 422 | 값이 규칙에 맞지 않음 | 입력 검증 오류, 빠진 값 |
| 500 | 서버 오류 | DB 연결 실패 등 |

### 2.5 오류 응답

모든 API가 같은 모양으로 답한다 (NFR-19).

```json
{ "detail": "현재 보유자산은 0 이상의 정수여야 합니다.", "field": "current_assets" }
```

| 값 | 내용 |
| --- | --- |
| `detail` | 사용자에게 그대로 보여 줄 문장. 항상 있다. |
| `field` | 문제가 된 값의 이름. 입력 검증 오류일 때만 있다. 화면이 그 입력란 아래에 문장을 보여 주는 데 쓴다. (6.1의 Q-3) |

- 오류의 내부 정보(코드 경로, SQL 문장)는 넣지 않는다 (NFR-11). 500일 때의 문장은 "잠시 후 다시 시도해 주세요."로 고정한다.
- FastAPI가 기본으로 내는 검증 오류는 모양이 다르다. 공통 처리기를 하나 두어 위 모양으로 바꾼다 (T-COMMON-08).
- 서버에 닿지 못한 경우(네트워크 오류)의 문장은 화면이 정한다. 문장은 와이어프레임에 적혀 있다.

## 3. API 정의

예시의 숫자는 와이어프레임과 같은 예시 값으로 계산한 것이다. 보유자산 5,000만 원, 월 저축 100만 원, 5년, 첫째 상품(최대 한도 3억 6,000만 원, 대출 비율 70%, 연 4.0%), 상환 30년이다.

### 3.1 자료 조회

#### A-01 `GET /api/loan-products` 대출 상품 목록

| 항목 | 내용 |
| --- | --- |
| 쓰는 화면 | P-03 대출상품 선택, 시나리오 탭 |
| 근거 | FR-LOAN-01, 02, 09, FR-DATA-06, T-LOAN-06 |
| 읽는 표 | `loan_products` |

응답 200

```json
{
  "products": [
    {
      "id": 1,
      "name": "[상품명]",
      "institution": "한국주택금융공사",
      "max_limit": 360000000,
      "ltv_ratio": 0.7,
      "annual_rate_pct": 4.0,
      "repayment_years_options": [10, 15, 20, 30],
      "max_house_price": 600000000,
      "eligibility_summary": "[자격 조건 요약]",
      "eligibility_text": "[자격 조건 문구]",
      "base_date": "2026-10-01",
      "source_url": "https://..."
    }
  ]
}
```

- 상환 기간 선택지는 DB에 "10,15,20,30"으로 들어 있다. 서버가 숫자의 목록으로 바꿔 준다.
- `max_house_price`가 null이면 상한이 없는 상품이다.

#### A-02 `GET /api/regions` 구와 동의 목록

| 항목 | 내용 |
| --- | --- |
| 쓰는 화면 | P-05의 구·동 선택, 지도 가운데의 동 이름 표시 |
| 근거 | FR-APT-02, FR-MAP-29, T-APT-01 |
| 읽는 표 | `apartments`, `apartment_prices` |

응답 200

```json
{
  "regions": [
    {
      "gu": "서구",
      "latitude": 35.1520,
      "longitude": 126.8900,
      "dongs": [
        { "dong": "치평동", "apartment_count": 23, "latitude": 35.1490, "longitude": 126.8450 }
      ]
    }
  ]
}
```

- 평균가가 있는 아파트가 한 곳이라도 있는 구와 동만 나온다.
- 위치는 그 구나 동에 있는 아파트 좌표의 평균이다 (명세서 부록 C). 좌표가 있는 아파트가 없으면 null이다.
- 지역 선택으로 지도를 옮길 때 이 위치를 쓴다. 지도 가운데의 동 이름도 이 목록에서 가장 가까운 동을 골라 표시한다. (6.1의 Q-7)

- 재무 조건이 필요 없어 GET이다. 구분과 여유·부족 금액은 A-05와 A-07이 준다.
- `areas`는 평균가가 낮은 순이다.
- `facilities`는 주변 시설이다 (FR-MAP-23, 2026-10-19). `data/load_facilities.py`가 카카오 장소 검색으로 미리 받아 `apartment_facilities`에 넣은 값을 그대로 준다. 서버는 카카오를 부르지 않는다 (NFR-08).
  - 순서: `subway`, `school`, `mart`, `convenience`, `hospital`, `elementary`, `middle`, `high`, `university`, `bus`.
  - `bus`는 가장 가까운 버스정류장이다 (2026-10-20 더함). 정보 탭의 줄로는 쓰지 않는다. 지도는 정류장 전체(A-28)를 띄우고, A-28을 못 읽을 때만 역세권이 아닌 아파트의 이 줄을 대신 띄운다.
  - `place_name`과 `distance`가 null이면 반경(`radius`, m) 안에 없는 것이다. `distance`는 직선거리(m)이고, 지하철역은 가장 가까운 출구(`exit_no`)까지다. 출구를 못 찾았으면 `exit_no`가 null이고 거리는 역까지다.
  - `latitude`, `longitude`는 그 곳의 좌표다 (지하철역은 그 출구). 지도에서 고른 아파트와 시설을 잇는 데 쓴다. 화면은 이 좌표를 쓰고 장소 검색을 부르지 않는다 (2026-10-19).
  - 아직 받지 않았으면 빈 목록이고 `facilities_base_date`는 null이다.
- 없는 번호면 404, "아파트를 찾을 수 없습니다."

- **자금 부족 표시 스위치**는 화면이 처리한다. 서버는 자금이 부족한 아파트도 항상 준다 (FR-APT-04).

- 목표 기간이 "지금"이면 `within`은 나오지 않는다 (C-09).

### 3.3 재무정보 저장

로그인한 사용자의 값을 DB에 둔다. 각 입력 단계의 마지막 버튼을 누를 때 저장한다 (FR-PROFILE-04).

**재무정보는 회원 한 명에 3개까지다 (2026-10-21).** 화면의 "재무정보 1 ~ 3" 칸 하나가 `profiles`의 한 줄이다 (DB 설계서 3.2).

- 재무정보가 하나도 없을 때 A-09를 부르면 "재무정보 1"을 새로 만든다 (예전과 같다).

#### 3.3.1 재무정보 3개 (A-29 ~ A-34, 2026-10-21)

로그인한 시작 화면(P-01)이 쓴다. 재무정보 하나의 모양은 A-08의 `profile`에 아래 세 값을 더한 것이다. A-08 ~ A-11의 응답에도 같은 세 값이 들어간다.

| 값 | 내용 |
| --- | --- |
| `id` | 재무정보 번호. 지운 번호는 다시 쓰지 않는다. |
| `slot` | 칸 번호. 1, 2, 3 |
| `name` | 칸 이름. 1 ~ 10자. 처음에는 "재무정보 1"처럼 칸 번호로 짓는다. |

##### A-29 `GET /api/profiles` 내 재무정보 목록

응답 200

```json
{
  "profiles": [
    { "id": 7, "slot": 1, "name": "재무정보 1", "age": 29, "annual_income": 36000000, "current_assets": 50000000,
      "loan_choice": "product", "loan_product_id": 1, "loan_product_name": "[상품명]", "repayment_years": 30,
      "monthly_saving": 1000000, "target_years": 5, "updated_at": "2026-10-21T10:00:00" }
  ],
  "selected_id": 7
}
```

- 칸 번호 순서다. 없으면 `profiles`가 빈 목록이고 `selected_id`가 null이다.
- `selected_id`는 마지막으로 고른 재무정보(A-34)다. 고른 적이 없거나 고른 것을 지웠으면 칸 번호가 가장 작은 재무정보다.

##### A-30 `POST /api/profiles` 재무정보 더하기

요청: 일곱 값을 한 번에 보낸다. 대출 선택은 A-10과, 금액은 A-09, A-11과 같은 규칙이다.

```json
{ "age": 29, "annual_income": 36000000, "current_assets": 50000000,
  "loan_choice": "product", "loan_product_id": 1, "repayment_years": 30,
  "monthly_saving": 1000000, "target_years": 5 }
```

- 응답 201 `{ "profile": { ... } }`. 칸 번호는 비어 있는 가장 작은 번호, 이름은 "재무정보 칸번호"다.
- 이미 3개면 422 "재무정보는 3개까지 저장할 수 있습니다."
- 주민등록번호는 받지 않는다. 화면이 계산한 만 나이만 보낸다 (NFR-25).

##### A-31 `PUT /api/profiles/{id}` 재무정보 고치기

요청은 A-30과 같다. 응답 200 `{ "profile": { ... } }`. 이름과 칸 번호는 그대로다.

##### A-32 `PUT /api/profiles/{id}/name` 이름 바꾸기

요청 `{ "name": "신혼집" }`. 앞뒤 빈칸을 뗀 뒤 1 ~ 10자. 응답 200 `{ "profile": { ... } }`

- 비었거나 10자를 넘으면 422 "이름은 1자 이상 10자 이하로 입력해 주세요." (field `name`)

##### A-33 `DELETE /api/profiles/{id}` 재무정보 지우기

응답 204. 그 재무정보로 한 찜은 지우지 않는다. 찜의 `profile_id`가 null이 되고, 화면은 "삭제된 재무정보"로 묶는다. 같은 칸 번호로 새로 만들어도 예전 찜과 이어지지 않는다 (번호가 다르다).

##### A-34 `PUT /api/profiles/{id}/select` 고른 재무정보 남기기

요청 본문은 없다. 응답 204. 시작 화면에서 "선택한 정보로 지도 보기"를 누를 때 부른다. 다음에 로그인했을 때 A-29의 `selected_id`가 이 번호다.

- A-29 ~ A-34 모두 남의 번호나 없는 번호면 404 "재무정보를 찾을 수 없습니다."

- A-24 비슷한 아파트의 기준 (2026-10-14에 정함)
  - 기준 가격은 고른 아파트의 고른 면적의 평균가다. 없는 아파트나 면적이면 404 "아파트를 찾을 수 없습니다."

  - 순서는 같은 동이 먼저, 그다음 같은 구의 다른 동이다. 그 안에서 기준 가격과의 차이가 작은 순, 같으면 아파트 번호 순.
  - 순서 `sort`: 모두 같은 동 먼저. similar는 기준 가격과의 차이 순, area는 고른 면적과 전용면적 차이 순(같으면 가격 차이), newest는 준공 연도가 최근인 순(모르면 뒤, 같으면 가격 차이). 다른 값이면 422.
  - 한 번에 여섯 곳 (2026-10-18, 예전에는 세 곳). 화면의 '다른 곳 보기'는 `next_offset`을 `offset`으로 보내 다음 여섯 곳을 받는다. 끝까지 보면 `next_offset`이 0이라 처음 여섯 곳으로 돌아간다. `offset`이 후보 수 이상이면 0부터 준다. 음수면 422.
  - 구분, 부족자금, 대출금액은 A-05와 같은 규칙으로 매긴다.

### 3.6 A-26 `GET /api/config` 화면 설정

지도를 그리려면 화면이 카카오 JavaScript 키를 알아야 한다. 서버가 이 API로 키를 준다 (아키텍처 문서의 T-4). 지도 화면이 열릴 때 한 번 부른다.

```json
{ "kakao_js_key": "..." }
```

JavaScript 키는 브라우저에 드러나는 값이다. 등록한 사이트 주소에서만 동작하게 해서 보호한다 (NFR-04). REST API 키와 공공데이터 인증키는 절대로 화면에 주지 않는다.
