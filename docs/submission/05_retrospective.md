## 김해원 (팀장 · 입력과 공통)

> 기능보다 먼저 정한 약속(문서 · 규칙)이 네 명을 한 방향으로 움직였습니다

**좋았던 점**
- 요구사항 · 화면 · DB · API 문서를 먼저 정리하고 시작
- CLAUDE.md · Git 규칙 · develop 받기 안내서로 같은 방식으로 작업
- PR을 검토하며 팀원들이 빠르게 성장하는 모습

**어려웠던 점**
- 지도 멈춤 · 캐시처럼 원인을 찾기 어려운 문제
- 네 명의 작업을 하나로 합치는 통합
- 2주라는 짧은 기간 안의 일정 관리

**배운 점**
- 설계가 분명해야 AI도 정확하게 만든다
- 팀장은 직접 만드는 것보다 잇고 정리하는 역할
- 다음에는 배포를 더 일찍 준비하기

## 김목산 (자료와 탐색)

> 의견과 피드백을 빨리 주고받아 분쟁 없이 재밌게 마무리했습니다

**좋았던 점**
- 꼼꼼한 팀장님 덕분에 무사히, 재밌게 작업
- 각자 의견을 잘 내고 피드백을 빨리 받아들임

**어려웠던 점**
- 옛 지역코드를 최신으로 바꾸고, 건축물대장 수집이 가장 오래 걸림
- 평균가 기간을 13개월 → 12개월로 바로잡기
- 세대수 맞추기와 없는 세대수 직접 찾기
- 조건창이 올라올 때 지도가 밀리는 문제
- 가입 · 탈퇴 API (비밀번호 · 가입 동의가 저장되지 않던 문제)
- "이어서 하기"에도 조건을 다시 넣어야 하던 흐름 고치기

**배운 점**
- 코딩은 AI가 거의 해 주지만 UI는 우리가 정해야 한다
- 문제를 하나씩 해결하며 많이 배우고 늘었음

## 박채은 (대출과 계산)

> 기획부터 구현, 개선까지 하나의 서비스가 만들어지는 흐름을 경험했습니다

**좋았던 점**
- 비전공자 · 2주 입원 공백으로 걱정이 많았지만 팀 덕분에 많이 배움
- 전체 방향 · 구조 설계와 세심한 피드백으로 작업이 하나로 이어짐

**아쉬운 점**
- 아직 모든 기술 원리와 구현 과정을 완벽히 이해하지는 못함

**배운 점**
- 맡은 기능을 직접 고치고 확인하며 반복해 개선하는 재미
- 개별 기능이 전체 서비스 안에서 하는 역할을 이해
- 주어진 작업을 넘어 서비스 전체 흐름을 경험

## 안세환 (지도와 아파트 창)

> 처음의 문서와 가이드라인이 얼마나 중요한지 배웠습니다

**좋았던 점**
- Git 사용법과 아침마다 최신화하는 법을 미리 안내받아 계획적으로 작업
- 인원별 피드백 · 질문방으로 소통
- 잘 정리된 문서, 그리고 CLAUDE.md가 진짜 킥

**어려웠던 점**
- UI의 세세한 디테일은 AI로 작업해도 직접 잡아 줘야 함
- 로드뷰처럼 사소한 문제로 화면이 안 나오던 경우

**배운 점**
- 시작할 때의 문서 작성과 가이드라인의 중요성
- Git 사용법
- 피드백으로 소통하며 느낀 협업의 재미
