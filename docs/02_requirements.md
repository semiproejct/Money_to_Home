## 1. 문서 개요

### 1.1 문장 형식

- 시스템이 할 일: "시스템은 ~해야 한다."
- 사용자가 할 수 있는 일: "사용자는 ~할 수 있어야 한다."
- User Story: "사용자는 [기능]을 통해 [목적]을 수행할 수 있다."

### 1.2 ID 규칙

| 종류 | 형식 | 예 |
| --- | --- | --- |
| 기능 요구사항 | `FR-영역-번호` | FR-LOAN-01 |
| 비기능 요구사항 | `NFR-번호` | NFR-01 |
| 계산 규칙 | `C-번호` | C-05 |
| User Story | `US-영역-번호` | US-LOAN-01 |
| Task | `T-영역-번호` | T-LOAN-01 |
| 결정 사항 | `D-번호`, `N-번호`, `P-번호` | D-17, N-01 |
| 조사 값 | `R-번호` | R-03 |

번호가 중간에 비어 있는 것은 회의에서 제외한 항목이다. 다른 표와 어긋나지 않도록 번호를 다시 매기지 않았다. 제외한 항목은 부록 A에 있다.

### 1.3 분류 (MoSCoW)

| 분류 | 기준 | 구현 단계 |
| --- | --- | --- |
| Must | 없으면 핵심 흐름이 끊긴다. | 1차 |
| Should | 흐름은 동작하지만 없으면 서비스로서 부족하다. | 2차 |
| Could | 있으면 좋다. 일정이 남을 때 한다. | 3차 |
| Won't | 이번 MVP에서는 하지 않는다. | 없음 |

요구사항이 어떤 결정이나 검토로 추가되고 수정되었는지는 부록 B에 있다.

### 2.4 계산에 적용하는 가정

모든 계산은 아래 가정을 따른다. 결과 화면에도 이 가정을 표시한다(FR-COMMON-08).

| 항목 | 가정 |
| --- | --- |
| 주택 보유 | 사용자는 무주택자다. |
| 대출 자격 | 선택한 상품의 자격을 충족한다. 심사와 채무자의 상황을 고려하지 않는다. |
| 나이, 연 소득 | 계산에 쓰지 않는다. 화면 표시용으로만 받는다. 나이는 주민등록번호 앞 7자리로 계산한 만 나이다. |
| 대출 없이 계산 | 사용자가 고르면 예상 대출금액을 0원으로 두고 자기자금만으로 계산한다. 이때 대출에 관한 가정은 적용하지 않는다. |
| 기존 부채 | 고려하지 않는다. |
| 신용, 월 지출 | 고려하지 않는다. |
| 미래 집값 | 예측하지 않는다. 현재 평균가를 그대로 쓴다. 대신 허용 상승률을 함께 보여 준다. |
| 금액 기준 | 모든 금액은 현재 가치 기준이다. 저축 이자와 소득 증가도 반영하지 않는다. |
| 예상 대출금액 | 그 아파트에 대해 받을 수 있는 최대 금액으로 본다. |
| 대상 주택 가격 상한 | 넘어도 계산에서 빼지 않고 표시만 한다. |
| 상환 방식 | 원리금균등 상환으로 고정한다. |
| 금리 | 상품별 대표 금리 하나를 쓴다. |

### 2.5 범위 밖 (Won't)

이번 MVP에서 하지 않는 것이다. 제외한 요구사항의 ID와 문장은 부록 A에 있다.

| 항목 | 사유 |
| --- | --- |
| 대출 자격 심사, 상환 부담 계산 | 자격 충족을 가정한다. |
| 집값 변동 가정 선택, 금리 변경 | 입력을 단순화한다. 가능하면 최근 변동률만 화면에 표시한다. (Could) |
| 미래 집값·금리 예측 | 예측하지 않는다. |
| 아이디 찾기, 비밀번호 초기화 | 연락처를 수집하지 않아 본인 확인을 할 수 없다. |
| 기존 대출, 추가 자격 항목 입력 | MVP에서 고려하지 않는다. |
| 최근 거래 내역 상세 | 평균가와 거래 건수로 대신한다. |
| 세대수 검색 | 세대수 자료가 연결되지 않는 아파트가 있어 검색 조건으로는 쓰지 않는다. 표시는 한다. |
| 실시간 매물, 모든 은행의 대출 상품 | 공공 실거래 데이터와 대표 상품 2개로 한정한다. |
| 계좌 연동, 신용조회, 대출 신청 | 외부 인증과 민감 정보 처리가 필요하다. |
| 전세·월세, 청약, 아파트 외 주택 | 대출 상품과 데이터가 다르다. |
| 광주 5개 구 외 지역 | 한 지역을 완성한 뒤 확장한다. |
| 아파트 사진 크롤링, 평면도 | 약관과 저작권 문제가 있다. |

| FR-MAP-12 | 시스템은 지도를 불러오지 못하면 그 사실을 안내하고, 검색 결과 목록은 계속 쓸 수 있게 해야 한다. | Should |
| FR-MAP-17 | 사용자는 창의 손잡이를 위로 끌어 창을 키우고, 아래로 길게 끌어 닫을 수 있어야 한다. | Should |
| FR-MAP-18 | 사용자는 30% 상태의 창을 좌우로 밀어 이전 아파트와 다음 아파트로 넘길 수 있어야 한다. | Should |
| FR-MAP-19 | 시스템은 지도의 아파트 표시에 실거래 평균가와 공급면적을 기본으로 함께 보여 주어야 한다. 구분은 표시의 색으로 나타낸다. 여유 또는 부족 금액은 표시에 쓰지 않고, 표시를 눌렀을 때 아래 창에서 보여 준다. 면적대가 여러 개인 아파트는 검색 조건에 맞는 면적대 중 평균가가 가장 낮은 것을 쓴다. 공급면적을 알 수 없으면 전용면적을 쓴다. | Should |
| FR-MAP-20 | 시스템은 지도가 넓게 보일 때 동마다 하나의 표시로 그 동의 목표 가능한 아파트 수를 보여 주어야 한다. | Should |
| FR-MAP-21 | 사용자는 동의 표시를 눌러 그 동으로 지도를 확대하고, 구분별 아파트 수와 목록을 볼 수 있어야 한다. 목록은 지금 가능한 아파트부터 보여 준다. | Should |
| FR-MAP-22 | 시스템은 사용자가 지도를 옮기거나 확대·축소하면 지도에 보이는 영역의 아파트로 표시와 목록을 바꿔야 한다. | Should |
| FR-MAP-24 | 사용자는 현재 위치 버튼을 눌러 지도를 자신의 위치로 옮기고 그 위치를 지도에서 볼 수 있어야 한다. 위치 권한을 거부했거나 위치가 광주 5개 구 밖이면 지도를 옮기지 않고 그 사실을 안내한다. | Should |
| FR-MAP-25 | 시스템은 지도에 확대 버튼과 축소 버튼을 두어야 한다. | Should |
| FR-MAP-26 | 시스템은 지도의 축척을 표시해야 한다. | Should |
| FR-MAP-27 | 시스템은 아래 창이 열린 상태에서 브라우저의 뒤로 가기를 누르면 이전 화면으로 가지 않고 창을 닫아야 한다. 목록에서 아파트를 연 상태라면 목록으로 돌아간다. | Should |
| FR-MAP-28 | 시스템은 광주 5개 구의 경계를 선으로 표시하고, 경계 밖의 지도를 흐리게 보여 주어야 한다. | Should |
| FR-MAP-29 | 시스템은 사용자가 지도를 옮기면 지도 가운데가 속한 동의 이름을 보는 지역으로 표시해야 한다. (2026-10-18 새 스타일에서 구·동 선택 버튼을 없애고 목록 머리와 조건 창의 지역에 보인다) | Should |
| FR-MAP-30 | 시스템은 지도 화면의 내 조건 요약에 목표 가능 가격(C-08)을 표시해야 한다. 대출 없이 계산하기를 선택했으면 그 사실을 함께 표시한다. | Should |
| FR-MAP-31 | 시스템은 광주 5개 구 전체가 보일 만큼 지도가 넓게 보일 때 구마다 하나의 표시로 그 구의 목표 가능한 아파트 수를 보여 주어야 한다. 구의 표시를 누르면 그 구로 지도를 확대한다. | Should |
| FR-MAP-09 | 시스템은 아파트 정보 탭을 전체로 올렸을 때 헤더 바로 아래 맨 위에 그 위치의 로드뷰를 보여 주어야 한다. | Could |
| FR-MAP-10 | 시스템은 로드뷰가 없으면 기본 이미지를 보여 주어야 한다. | Could |
| FR-MAP-23 | 시스템은 선택한 아파트의 주변 시설(지하철역, 학교, 대형마트, 편의점, 병원)에서 가장 가까운 곳과 그곳까지의 거리를 보여 주어야 한다. 값은 카카오 장소 검색으로 미리 받아 DB에 두고, 받은 날을 함께 보여 준다. 반경 안의 수는 DB에 두되 화면에는 적지 않는다 (2026-10-19 결정). | Could |

> - 아파트 이미지는 웹 크롤링으로 수집하지 않는다.
> - 지도의 표시는 아파트 하나에 하나다. 면적대가 여러 개인 아파트는 검색 조건에 맞는 면적대 중 평균가가 가장 낮은 것을 기준으로 구분한다.
> - 창을 끄는 범위는 손잡이와 머리 부분이다. 내용 영역은 스크롤만 된다. 창과 손동작의 세부 동작은 `03_ui_design.md` 5장을 따른다.
> - 웹 화면에서는 아래 창을 왼쪽 패널로 배치한다. 목록 패널, 아파트 패널, 지도의 순서로 놓는다.
> - "내 조건에 가장 맞는 순서"는 지금 가능, 목표 기간 안에 가능, 자금 부족의 순이고, 같은 구분 안에서는 평균가가 목표 가능 가격(C-08)에 가까운 순이다.
> - 지도 화면에는 진행 바를 두지 않는다(FR-COMMON-09). 조건은 면적, 가격, 준공 연도의 칩으로 나눠 둔다.
> - 경계 밖을 흐리게 하는 방법은 반투명한 면을 덮는 것이다. 지도 그림 자체를 뿌옇게 만드는 기능은 지도 서비스에 없다. 카카오맵의 다각형은 좌표 배열을 두 개 넣으면 구멍이 뚫리므로, 바깥을 넓게 두른 좌표와 광주 5개 구 경계 좌표로 다각형 하나를 만든다.
> - 아래 창의 30%는 240픽셀보다 작아지지 않게 하고, 80%는 지도가 140픽셀 이상 남게 한다. 웹 화면의 패널에는 단계가 없다.
> - 지도의 표시는 넓게 볼수록 구, 동, 아파트의 순으로 바뀐다. 동 표시와 아파트 표시가 바뀌는 확대 수준은 정했다 (2026-10-13). 카카오맵의 확대 수준 6부터(더 넓게 보면) 동 표시, 5 이하는 아파트 표시다. 동 하나를 볼 때 5, 구 전체를 볼 때 7로 옮긴다. 구 표시가 나오는 수준은 2차에 정한다.
> - 자금 부족 표시의 스위치는 범례 안에 두지 않고 조건 칩 옆에 둔다. 정렬은 목록의 머리에서만 바꾼다.
> - 아파트 표시는 집 모양이다. 위 띠에 공급면적, 가운데에 실거래 평균가, 아래에 구분과 여유 또는 부족 금액을 쓴다. 띠의 색과 테두리로 구분을 나타낸다. 표시 안의 금액은 "3.0억", 1억 원 미만은 "6.5천"처럼 줄여 쓴다.
> - 아파트 정보 탭을 전체로 올리면 맨 위에 로드뷰(없으면 기본 이미지), 그 아래에 기본 정보, 주변 시설, 비슷한 아파트, 공유하기의 순서로 놓는다.

### 3.10 계산 규칙

팀 결정(D-01, D-03, D-04, D-05, D-07)으로 확정한 식이다. 서버의 공통 계산 모듈에 한 번만 구현한다(NFR-13). 금액은 모두 원 단위 정수다.

| 번호 | 항목 | 계산 | 예외와 반올림 | 관련 |
| --- | --- | --- | --- | --- |
| C-01 | 금액 단위 | 화면에서 만원 단위 정수로 받은 값에 10,000을 곱해 원으로 바꾼다. |  | FR-PROFILE-20, NFR-12 |
| C-02 | 누적 저축액 | 월 저축 가능액 × 12 × 목표 연수 | 목표 기간 "지금"은 0년이며 0원이다. | FR-PLAN-04 |
| C-03 | 목표 시점 자기자금 | 현재 보유자산 + 누적 저축액 |  | FR-PLAN-05 |
| C-04 | 필요자금 (목표 부동산 가격) | 선택한 아파트와 면적대의 평균가 | 목표 시점에도 같은 값을 쓴다. | FR-RESULT-01, FR-PLAN-08 |
| C-05 | 예상 대출금액 (아파트 기준) | min(상품 최대 한도, 평균가 × 대출 비율) | 원 미만은 버린다. 대출 비율은 1 이하이므로 평균가를 넘지 않는다. | FR-LOAN-06, 12 |
| C-06 | 최대 예상 대출금액 (아파트 선택 전) | min(상품 최대 한도, 현재 보유자산 × 대출 비율 ÷ (1 − 대출 비율)) | 대출 비율이 1이면 상품 최대 한도로 한다. 원 미만은 버린다. | FR-LOAN-06 |
| C-07 | 예상 월 상환액 | 원리금균등 상환. 대출금액 × m × (1+m)^N ÷ ((1+m)^N − 1). m은 연 금리 ÷ 12, N은 상환 연수 × 12 | 금리가 0이면 대출금액 ÷ N. 원 단위로 반올림한다. | FR-LOAN-07, 11 |
| C-08 | 목표 가능 가격 | min(자기자금 + 상품 최대 한도, 자기자금 ÷ (1 − 대출 비율)) | 자기자금은 "지금"이면 현재 보유자산, 그 외에는 C-03을 쓴다. | FR-APT-04 |
| C-09 | 3단계 구분 | 지금 가능: 현재 보유자산 + C-05 ≥ 평균가. 목표 기간 안에 가능: 지금 가능이 아니고 C-03 + C-05 ≥ 평균가. 자금 부족: 그 외 | 목표 기간이 "지금"이면 "목표 기간 안에 가능"은 나오지 않는다. | FR-APT-04, FR-MAP-02 |
| C-10 | 부족자금 | 평균가 − C-03 − C-05 | 음수면 절댓값을 여유자금으로 표시한다. | FR-RESULT-02, 03 |
| C-11 | 필요 월 저축액 | (평균가 − C-05 − 현재 보유자산) ÷ (12 × 목표 연수) | 부족자금이 0보다 클 때만 표시한다. 목표 기간이 "지금"이면 표시하지 않는다. 원 단위로 올린다. | FR-RESULT-04, FR-PLAN-09 |
| C-12 | 허용 상승률 | (목표 시점 자기자금으로 구한 C-08 ÷ 평균가)^(1 ÷ 목표 연수) − 1 | 목표 기간이 "지금"이거나 결과가 음수면 표시하지 않는다. 퍼센트의 소수 첫째 자리까지 표시하고 그 아래는 버린다. | FR-RESULT-09 |
| C-13 | 대출 없이 계산 | 예상 대출금액(C-05, C-06)을 0원으로 둔다. 목표 가능 가격(C-08)은 자기자금과 같아진다. | 월 상환액(C-07)은 계산하지 않는다. C-09 ~ C-12는 같은 식에 예상 대출금액 0원을 넣는다. | FR-LOAN-15 |

> - C-06은 대출상품 화면처럼 아파트를 아직 고르지 않은 단계에서 쓴다. 현재 보유자산으로 살 수 있는 가장 비싼 집을 기준으로 한 대출금액이다. 대출상품 화면에 이 금액을 보여 주기로 정했다.
> - 예상 대출금액은 그 아파트에 대해 받을 수 있는 최대 금액으로 계산한다. 여유자금이 있어도 대출금액을 줄이지 않는다.
> - 대상 주택 가격 상한은 계산에 쓰지 않고 표시만 한다. (FR-LOAN-14)

| 구간 | 내용 |
| --- | --- |

| 8~11일째 | 2차 구현 |
| 12~14일째 | 통합 점검, 계산 검증, 발표 준비. 시간이 남으면 3차 |

- AI 도구로 코드 작성은 빨라지지만 데이터 준비, 통합, 검증에 드는 시간은 줄지 않는다. 그래서 범위를 넓히지 않았다.
- 일정이 밀리면 이 순서로 줄인다: 3차 전체 → 탐색 조건 확장 → 입력 편의 → 회원 기능.

## 8. 남은 결정과 확인 사항

**사용 방법**

1. 아래 표의 `결정` 칸을 채운다. 선택지 번호만 적어도 된다.
2. 채운 표를 Claude에게 그대로 붙여 넣고 "02_requirements.md에 반영해 줘"라고 요청한다.
3. 일부만 결정했다면 결정한 줄만 붙여 넣어도 된다.

요청 예시:

```
아래 결정을 02_requirements.md에 반영해 줘.
D-17: ① 카카오맵
N-01: ①
N-05: ②
아이디 규칙: 4~20자로 변경
```

### 8.1 결정이 필요한 사항

본문은 "본문의 기본값"대로 써 두었다. 결정이 없으면 기본값대로 구현한다.

| 번호 | 질문 | 선택지 | 본문의 기본값 | 결정 |
| --- | --- | --- | --- | --- |
| N-06 | FR-PLAN-06의 변동률을 어떤 데이터로 구하는가 (Could) | ① 한국부동산원의 구 단위 매매가격지수 ② 실거래 데이터로 직접 계산 | 없음. ②는 12개월 데이터로는 구할 수 없어 수집 기간을 24개월 이상으로 늘려야 한다. 3차 전에 정한다. |  |
| N-07 | 구별 변동 그래프(FR-PLAN-10, Could)를 어떻게 그리는가 | ① 서버에서 Matplotlib으로 그림을 만들어 보여 준다 ② 화면용 차트 라이브러리로 그린다 | 없음. 3차 전에 정한다. 변동률 계산 자체는 Pandas로 한다. |  |

검토하면서 기본값으로 정해 둔 값(아이디 규칙, 반올림 방식 등)은 부록 C에 있다. 다른 값을 원하면 같은 방법으로 요청한다.
