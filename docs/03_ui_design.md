## 2. 화면 흐름과 목록

### 2.1 흐름

```
시작 ─ 로그인 없이 시작 ─→ 재무정보 → 대출상품 → 저축 계획 → 지도(메인)
  │                          (주민등록번호   (상품 + 기간      (월 저축액,      │
  │                           앞 7자리,      또는 대출 없이)    목표 기간)     ├ 구를 누름 → 그 구로 확대
  │                           연 소득,                                       ├ 동을 누름 → 30% 창: 그 동의 아파트
  │                           보유자산)                                      │      └ 카드를 누름 → 80% 창: 그 아파트
  └─ 로그인 ⇄ 회원가입 ─→ 저장한 값이 채워진 재무정보                          ├ 아파트를 누름 → 30% 창: 그 아파트
                                                                           │      └ 올리면 80% → 전체
                                                                           └ 수정 → 입력 단계
```

- 로그인하지 않아도 모든 흐름을 쓸 수 있다. 로그인은 저장에만 필요하다.
- 가입을 마치면 바로 로그인된 상태가 된다.
- 로그인한 뒤 30분 동안 요청이 없으면 로그아웃하고 시작 화면으로 보낸다. 입력하던 값은 브라우저에 남는다.
- 새로 고치면 보던 단계와 질문으로 돌아온다. 값은 탭을 닫거나 "처음부터 다시 입력"을 누르기 전에는 지우지 않는다.

### 2.2 화면 목록

| 번호 | 화면 | 종류 | 진행 바 | 구현 |
| --- | --- | --- | --- | --- |
| P-01 | 시작 | 페이지 | 없음 | 1차 |
| P-02 | 재무정보 입력 | 페이지 | 1/4 | 1차 |
| P-03 | 대출상품 선택 | 페이지 | 2/4 | 1차 |
| P-04 | 저축 계획 | 페이지 | 3/4 | 1차 |
| P-05 | 지도 (메인) | 페이지 | 없음 | 1차 |
| P-06 | 아래 창 (구, 동, 목록, 아파트) | P-05 위에 뜨는 창 | 없음 | 1차 |
| P-07 | 로그인 | 페이지 | 없음 | 2차 |
| P-08 | 회원가입 | 페이지 | 없음 | 2차 |
| P-09 | 저장한 결과 (목록, 열어 보기) | 페이지 | 없음 | 3차 |
| P-10 | 비밀번호 변경 | 페이지 | 없음 | 3차 |
| P-11 | 회원 탈퇴 | 페이지 | 없음 | 3차 |
| P-12 | 공유받은 아파트 (`share.html`) | 페이지 | 없음 | 3차 (2026-10-19) |

P-09 ~ P-11은 헤더의 계정 메뉴로 들어간다. 로그인하면 헤더의 "로그아웃" 자리가 아이디 버튼이 되고, 누르면 메뉴가 열린다 (3차).

- 2026-10-21: 찜한 시나리오 목록(P-09 목록)은 로그인한 시작 화면(P-01)의 재무정보 칸 아래로 옮겼다 (4.3.1). `saved.html`은 하나 열어 보기만 쓰고, 주소에 번호가 없으면 시작 화면의 찜 목록(`index.html#saved`)으로 보낸다.
- 2026-10-21: 지도 화면에는 헤더가 없으므로 조건 줄의 "로그인" 자리를 로그인했으면 "마이페이지 ▾"로 바꾼다. 메뉴는 내 조건(지금 고른 재무정보 이름 ›) · 찜한 시나리오 · 로그아웃(빨간 글자) 세 줄이다. 비밀번호 변경과 회원 탈퇴는 메뉴에 두지 않는다.

## 3. 공통 구조

### 3.1 뼈대

| 영역 | 내용 | 나오는 화면 |
| --- | --- | --- |
| 헤더 | 모바일에는 두지 않는다. 서비스 이름(로고)도 두지 않는다. 입력 화면은 헤더 자리(52px)를 흰 여백으로 둔다. 웹(1200px 이상)에서도 헤더 줄은 없고 로고(동전 그림 + "머니 to 홈")만 왼쪽 위(왼쪽에서 132px)에 띄운다. 누르면 시작 화면 (2026-10-19) | 웹의 입력 화면 여덟 개 |
| 스플래시 | 시작 화면을 탭에서 처음 열 때만 1초 동안 파란 바탕에 로고와 "머니 to 홈". 같은 탭에서 다시 오거나 새로 고침하면 띄우지 않는다. 웹에서는 띄우지 않는다 (2026-10-19) | P-01 (모바일) |
| 진행 바 | 얇은 네 칸 막대와 "2/4 대출상품". 왼쪽의 ‹ 로 이전 화면에 간다. 눌러서 이동하지는 않는다. | P-02 ~ P-04 |
| 내 조건 줄 | 지도 화면의 맨 위에 있다. 목표 가능 가격, 수정, 로그인. 대출 없이 계산이면 그 사실을 함께 적는다. 로그인했으면 로그인 자리에 로그아웃을 둔다. 문장이 자리보다 길면 "목표 가능 가격"을 뺀 짧은 문장으로 바꾸고, 그래도 넘치면 말줄임표로 자른다. | P-05, P-06 |
| 본문 | 화면별 내용 | 전체 |
| 아래 버튼 | 화면 아래에 붙는 버튼 하나. 키패드가 올라오면 키패드 바로 위에 붙는다. | P-01 ~ P-04, P-07, P-08 |
| 푸터 | 두지 않는다. | 없음 |

### 3.2 반응형

| 구간 | 폭 | 배치 |
| --- | --- | --- |
| 모바일 (기본) | ~767px | 한 단. 지도 화면은 지도 전체와 아래 창 |
| 태블릿 | 768~1199px | 모바일과 같고 여백만 조정 |
| 웹 | 1200px~ | 입력 화면은 가운데 흰 기둥(폭 560px, 안쪽 480px) 하나, 양옆은 회색 (2026-10-19. 처음 계획한 두 단에서 바꿈). 지도 화면은 왼쪽 패널과 지도 (아직 만들지 않음) |

모바일과 웹을 다른 페이지로 만들지 않는다. 같은 HTML의 배치만 미디어 쿼리로 바꾼다. 웹에서는 아래 창이 왼쪽 패널이 되고, 패널에는 30%, 80% 같은 단계가 없다. 왼쪽부터 목록 패널, 아파트 패널, 지도의 순서다. 목록과 아파트 정보가 나란히 보이고, 목록 패널은 접을 수 있다 (와이어프레임 W7 ~ W10).

### 3.3 표기 규칙

| 항목 | 규칙 |
| --- | --- |
| 금액 입력 | 만 원 단위 정수. 천 단위 쉼표를 자동으로 넣고 아래에 "1억 2,000만 원"처럼 읽어 준다. |
| 금액 표시 | 만원 단위로 반올림. "3억 2,500만 원", "8,500만 원" |
| 구분 | 지금 가능, 기간 내 가능, 자금 부족. 색은 팔레트 F 라임이다: 지금 가능은 파랑, 기간 내 가능은 라임, 자금 부족은 빨강. 지도의 표시는 색으로 나누고, 범례를 처음부터 펼쳐 색의 뜻을 알린다. 배지, 칩, 금액에는 글자를 함께 적는다. |
| 면적 | 8장 |
| 쓰지 않는 말 | "구매 가능", "승인", "추천", "10년 후 집값" |
| 누르는 영역 | 가로세로 44픽셀 이상 |
| 단계 표시 | 2차 기능에는 "2차", 3차 기능에는 "3차"를 와이어프레임에 붙인다. |

### 3.4 예외 상태의 공통 규칙

| 상황 | 화면 |
| --- | --- |
| 입력 오류 | 그 입력란 바로 아래에 문구. 설명 줄의 자리를 써서 화면이 밀리지 않는다. 버튼은 꺼진다. |
| 불러오는 중 | 내용 자리에 회색 자리 표시. 버튼에는 진행 중 표시 |
| 서버나 네트워크 오류 | 버튼 위나 화면 아래에 한 줄 안내. 입력한 값은 지우지 않는다. 오류의 내부 정보는 보여 주지 않는다. |
| 입력이 빠진 채 지도에 들어옴 | 계산하지 않고 빠진 단계로 안내한다. |

## 4. 입력 화면 (P-01 ~ P-04)

### 4.1 받는 값

| 번호 | 화면 | 값 | 형식 | 범위 | 계산에 쓰는가 |
| --- | --- | --- | --- | --- | --- |
| 1 | P-02 | 주민등록번호 앞 7자리 | 앞 6자리와 뒤 첫째 자리, 숫자 | 실제 날짜, 만 15세 ~ 100세 | 쓰지 않음. 만 나이를 표시만 한다. |
| 2 | P-02 | 연 소득 (세전) | 만 원 단위 정수 | 0 ~ 100억 원 | 쓰지 않음 |
| 3 | P-02 | 현재 보유자산 | 만 원 단위 정수 | 0 ~ 100억 원 | 씀 |
| 4 | P-03 | 대출 방법 | 상품 두 개와 "대출 없이 계산" 중 하나 | 기본 선택 없음 | 씀 |
| 5 | P-03 | 상환 기간 | 고른 상품이 제공하는 기간 중 하나 | 상품을 골랐을 때만 | 씀 |
| 6 | P-04 | 월 저축 가능액 | 만 원 단위 정수 | 0 ~ 10억 원 | 씀 |
| 7 | P-04 | 목표 기간 | 지금, 3년, 5년, 10년 | 기본 선택 없음 | 씀 |

- 주민등록번호 앞 7자리는 브라우저에서 만 나이를 계산하는 데만 쓴다. 브라우저 저장소, DB, 서버 요청 어디에도 남기지 않는다. 뒤 첫째 자리가 1, 2, 5, 6이면 1900년대, 3, 4, 7, 8이면 2000년대로 본다.
- 값은 브라우저에 보관한다. 로그인했으면 각 화면의 마지막 버튼을 누를 때 DB에도 저장한다. 대출 선택도 저장한다.
- 잘못된 글자를 막지 않고 오류 문구로 알린다. 모바일에서는 숫자 키패드를 띄운다.

### 4.2 오류 문구

| 경우 | 문구 |
| --- | --- |
| 음수 | 0 이상의 숫자만 입력할 수 있습니다. |
| 소수 | 소수는 입력할 수 없습니다. 만 원 단위의 정수로 입력해 주세요. |
| 숫자가 아닌 값 | 숫자만 입력할 수 있습니다. |
| 없는 날짜, 미래 날짜 | 생년월일을 다시 확인해 주세요. |
| 나이 범위 밖 | 만 15세부터 100세까지 입력할 수 있습니다. |
| 금액 상한 초과 | 100억 원(1,000,000만 원)까지 입력할 수 있습니다. 월 저축 가능액은 10억 원 |

### 4.3 P-01 시작

| 상태 | 내용 | 단계 |
| --- | --- | --- |
| 기본 | 한 줄 소개, 세 단계 설명, 안내 문구, "로그인 없이 시작하기"(가장 큰 버튼) | 1차 |
| 기본 | 로그인, 회원가입 | 2차 |
| 로그인, 저장한 정보 있음 | ~~저장한 값, "이어서 하기", "처음부터 다시 입력"~~ → 재무정보 3칸과 찜한 시나리오 (4.3.1, 2026-10-21) | 2차 → 3차 |
| 로그인, 저장한 정보 없음 | ~~"시작하기"~~ → 빈 칸 "+ 재무정보 1 추가" (4.3.1). 이 탭에 입력을 다 마친 값이 있으면 재무정보 1로 저장해 둔다 | 2차 → 3차 |
| 기본 (로그인하지 않음) | 맨 아래 안내를 두 줄로: "로그인하면 재무정보를 저장하고 / 마음에 드는 아파트를 찜할 수 있습니다." (2026-10-21) | 3차 |
| 예외 | 저장한 정보를 불러오지 못함, 로그인 시간이 끝남 | 2차 |

### 4.3.1 로그인한 시작 화면: 재무정보 3칸 + 찜한 시나리오 (2026-10-21)

로그인한 사람만 본다. 한 페이지를 위아래로 스크롤해 두 부분을 오간다. 각 부분은 적어도 한 화면 높이라 맨 위에 맞추면 그 부분만 보인다.

**위: 재무정보 3칸**

| 요소 | 내용 |
| --- | --- |
| 오른쪽 위 | 회색 글자 버튼 "찜한 시나리오 보기 ↓". 누르면 아래로 부드럽게 스크롤 |
| 제목 | "○○님," / "재무정보를 골라 주세요". 설명 "고른 재무정보로 지도를 보여 줍니다." |
| 칸 (세로로 세 개까지) | 이름(연필을 누르면 그 자리에서 바꾼다, ✓ ✕, 10자까지) · 오른쪽 위 글자 링크 "수정  삭제". 큰 글자 넷(대출 상품, 상환 기간, 월 저축 가능액, 목표 기간), 선 아래 작은 한 줄(만 나이 · 연 소득 · 보유자산). 고른 칸은 파란 테두리와 연한 파란 바탕 |

- 처음 고른 칸은 마지막으로 지도를 본 칸이다 (A-29의 `selected_id`).
- 추가 · 수정 창 (아래에서 올라오는 창, 웹은 가운데): 주민등록번호 앞 7자리(수정이면 `●●●●●● - ●`와 "만 N세", [다시 입력]), 연 소득, 현재 보유자산, 대출 상품, 상환 기간, 월 저축 가능액, 목표 기간. 금액의 규칙과 오류 문구는 입력 화면과 같다 (100억, 10억 상한. 칸 아래에 바로). 비었거나 틀린 칸이 있으면 [추가 · 저장]을 끈다.
- 추가 창은 앞 번호 재무정보(2를 더하면 1, 3을 더하면 2)의 값을 아주 흐린 회색으로 칸 안에 보여 준다. 빈 칸에서 Tab을 누르면 그 값이 들어간다. 고르는 값(대출 상품, 상환 기간, 목표 기간)은 앞 재무정보의 값으로 골라 둔다.
- 창이 열린 동안 뒤 화면은 스크롤되지 않는다. 바깥을 누르거나 Esc를 눌러도 닫히지 않는다 ([취소]나 [추가 · 저장]으로만).
- 삭제는 확인 창 "재무정보 N을(를) 삭제할까요? 찜한 시나리오는 그대로 남습니다."

| 요소 | 내용 |
| --- | --- |
| 오른쪽 위 | 회색 글자 버튼 "↑ 재무정보 보기" |
| 제목 | "찜한 시나리오", 설명 "찜했을 때의 조건과 평균가로 계산한 값입니다." |

| 카드 위 줄 | 왼쪽 꼬리표 "재무정보 2 \| 지금 조건과 다름" (바탕 없이 #333 글자, 사이에 세로 줄), 오른쪽 구분 배지(아파트 창의 배지와 같은 모양)와 바로 옆 ♥ |

- "지금 조건과 다름": 찜할 때의 조건(보유자산, 월 저축, 목표 기간, 대출)이 그 재무정보의 지금 값과 다르다.

- ♥를 누르면 ♡로 바뀌고 찜이 지워진다 (A-35). 카드는 새로 고치거나 다른 화면에 다녀올 때까지 그 자리에 남고, ♡를 다시 누르면 다시 찜한다 (A-21).

- 휴대폰에서는 면적 · 금액 줄과 조건 줄의 글자를 1 ~ 2px 줄여 한 줄에 들어가게 한다.

### 6.2 넓게 볼 때의 표시

| 확대 수준 | 표시 | 누르면 |
| --- | --- | --- |
| 광주 5개 구 전체 | 구마다 하나. 구 이름과 목표할 수 있는 아파트 수 | 그 구로 확대 |
| 구 | 동마다 하나. 동 이름과 목표할 수 있는 아파트 수 | 그 동으로 확대하고 30% 창 |
| 동 | 아파트마다 하나 | 그 아파트의 30% 창 |

구 표시는 서로 겹치지 않게 벌려 둔다 (2026-10-18). 원끼리 16px 이상 떨어지고, 원의 가운데는 반드시 그 구의 경계 안에 있다. 자리는 가장 넓게 보는 수준(9)에서 한 번 정해 수준 7 ~ 9에서 그대로 쓰므로, 다른 구나 동을 눌렀다가 돌아와도 움직이지 않는다. 수준 9에서는 원을 56px로 줄인다. 남구는 서구 경계선에 걸치지 않게 손으로 조금 옮겼다 (`map-view.js`의 `GU_MARKER_NUDGE`).

목표할 수 있는 아파트 수는 지금 가능과 기간 내 가능을 더한 값이다. 동 표시는 연보라 동그라미에 동 이름과 숫자를 적는다. 동 표시를 누르면 그 동이 화면 가운데로 오면서 확대된다. 확대 수준은 정했다 (2026-10-13). 카카오맵의 확대 수준 6부터(더 넓게 보면) 동 표시, 5 이하는 아파트 표시다. 동 하나를 볼 때 5, 구 전체를 볼 때 7로 옮긴다. 구 표시가 나오는 수준은 2차에 정한다.

### 6.3 예외

입력이 빠졌을 때, 결과 없음, 불러오는 중, 지도를 불러오지 못함(목록을 전체 화면으로), 위치 권한이 꺼져 있음, 현재 위치가 광주 5개 구 밖.

## 7. 아래 창 (P-06)

### 7.1 동작

| 항목 | 내용 |
| --- | --- |
| 단계 | 30% → 80% → 전체. 비율은 헤더와 내 조건 줄을 뺀 지도 영역의 높이가 기준이다. |
| 높이의 한계 | 30%는 240픽셀보다 작아지지 않는다. 80%는 지도가 140픽셀 이상 남게 한다. |
| 여는 방법 | 지도의 표시를 누르면 30%, 목록의 카드를 누르면 80% |
| 키우는 방법 | 손잡이를 위로 끈다. 1차에는 손잡이를 누르면 다음 단계로 바뀐다. |
| 닫는 방법 | 아래로 길게 끌거나 닫기 버튼. 뒤로 가기를 누르면 페이지를 떠나지 않고 창이 닫힌다. |
| 끄는 범위 | 손잡이와 머리 부분. 내용 영역은 스크롤만 된다. |
| 지도 맞춤 | 누른 아파트가 창을 뺀 남은 영역의 가운데에 오게 한다. |
| 80% 이상일 때 | 검색창과 조건 칩을 숨긴다. |
| 전체일 때 (아파트 창) | 창이 내 조건 줄 뒤까지 올라가 로드뷰 윗부분(40px)이 반투명한 내 조건 줄 아래로 들어간다 (2026-10-18). 목록의 전체는 내 조건 줄 바로 아래부터다. |

### 7.2 동을 눌렀을 때 (30%)

구분별 개수 한 줄, "지금" 아파트의 첫 카드, 걸쳐 보이는 다음 카드. 개수를 누르면 그 구분으로 내려간다. "지금"이 없으면 그 사실을 알리고 다음 구분부터 보여 준다.

### 7.3 목록

| 요소 | 내용 |
| --- | --- |
| 모양 | iOS 그룹형 (2026-10-18). 창 전체(손잡이 줄과 스크롤 막대 자리 포함)가 회색 바탕이고, 무리마다 둥근 흰 판 안에 줄이 가는 선으로 나뉜다. |

- 목표 기간이 "지금"이면 필요 월 저축액과 허용 상승률을 보여 주지 않는다.
- 여유자금이 있으면 필요 월 저축액을 보여 주지 않는다.

## 8. 면적 표기

### 8.1 규칙

| 경우 | ㎡ | 평 |
| --- | --- | --- |
| 공급면적을 알 수 있음 | 111㎡ (전용 84㎡) | 34평 (전용 26평) |
| 공급면적을 알 수 없음 | 전용 59㎡ | 전용 18평 |

- 공급면적을 앞에, 전용면적을 괄호 안에 적는다.
- 버튼으로 ㎡와 평을 바꾼다. 평은 ㎡를 3.3058로 나눠 반올림한다. 전용면적의 평은 화면에 보이는 정수(84)가 아니라 실제 전용면적(84.94)으로 계산한다. 그래야 "전용 26평"이 나온다.
- 공급면적을 알 수 없는 아파트는 전용면적만 적고 "전용"을 붙인다.
- 계산과 실거래 연결에는 항상 전용면적을 쓴다. 공급면적은 표시용이다.

### 8.2 공급면적의 출처

| 자료 | 결과 |
| --- | --- |
| 실거래가 | 전용면적만 있다. |
| 광주 5개 구 아파트 현황 (2026년 8월 말) | 공급면적 칸이 1,268곳 중 826곳(65%)에서 비어 있다. 서구는 전부, 북구 85%, 광산구 77%가 없다. |
| 건축물대장 전유공용면적 | 전용면적과 주거공용면적을 더해 계산한다. 광천동 시험에서는 단지의 절반만 계산되었다. |
| **건축물대장과 대조한 구별 CSV** (팀원 작성) | 실거래 16,919건에 공급면적을 붙인 자료다. 면적대 1,848개 중 1,683개(91%)에 값이 있다. 이 자료를 쓴다. |

### 8.3 계산 방법

```
공급면적 = 전용면적(전유 부분) + 주거공용면적
```

| 구분 | 해당하는 용도 |
| --- | --- |
| 주거공용 (더함) | 계단, 복도, 벽체, 엘리베이터, 현관, 통로 |
| 기타공용 (뺌) | 주차장, 관리사무소, 경비실, 경로당, 주민공동시설, 기계실, 전기실, 창고, 지하실 |

- 공급면적이 있는 면적은 모두 표시한다. 없는 면적은 전용면적만 표시한다. 전용률 85% 기준은 쓰지 않기로 했다 (2026-10-11).
- 자료의 공급면적은 구한 방법이 여러 가지다: 대장의 주거공용을 더한 것, 공용 용도를 해석해 추정한 것, 같은 주소의 다른 세대 값을 빌린 것, 기존값을 그대로 둔 것. 방법은 DB에 함께 저장한다.
- 값은 정수로 올림되어 있다. 전용면적과 거의 같은 값도 몇 건 있다(예: 전용 59.88㎡에 공급 60㎡). 눈에 띄면 자료에서 고친다.
- 같은 면적대에서 값이 갈리면 거래에 가장 많이 나온 값을 쓴다.

### 12.2 화면 사이에 넘기는 값

화면이 바뀌어도 유지해야 하는 값이다. 브라우저의 탭 단위 저장소에 보관한다 (FR-PROFILE-11).

| 값 | 만드는 화면 | 쓰는 화면 | 비고 |
| --- | --- | --- | --- |
| 만 나이, 연 소득 | P-02 | P-01(저장한 정보), 입력 요약 | 표시용. 주민등록번호 앞 7자리는 보관하지 않는다. |
| 현재 보유자산 | P-02 | P-03 ~ P-06 | |
| 대출 방법 (상품과 상환 기간, 또는 대출 없이 계산) | P-03 | P-05, P-06 | |
| 월 저축 가능액, 목표 기간 | P-04, P-06(조건 바꿔 보기) | P-05, P-06 | |
| 보던 단계와 질문 | P-02 ~ P-04 | P-02 ~ P-04 | 새로 고쳤을 때 그 자리로 돌아오는 데 쓴다. |
| 지금 고른 재무정보의 번호와 이름 (`place.profile_id`, `place.profile_name`) | P-01 (로그인) | P-02 ~ P-06 | 입력 단계와 다시 계산의 저장(A-09 ~ A-11), 찜(A-21)이 이 번호로 간다. 조건 줄과 마이페이지 메뉴에 이름을 보인다 (2026-10-21). |
| 구, 동, 조건, 정렬, 면적 단위, 자금 부족 표시 | P-05 | P-05, P-06 | |
| 선택한 아파트와 면적 | P-05, P-06 | P-06 | |

- 값의 이름과 형식은 한 가지로 정해 네 명이 같이 쓴다. 각자 정하면 화면이 이어지지 않는다.
- 탭을 닫거나 "처음부터 다시 입력"을 누르기 전에는 지우지 않는다.
- 로그인했으면 각 입력 단계의 마지막 버튼을 누를 때 DB에도 저장한다. "이어서 하기"는 DB의 값으로 채운다.
- 계산에 필요한 값이 하나라도 빠진 채 지도에 들어오면 빠진 첫 단계로 안내한다. 이 확인은 공통 함수 하나로 만든다 (FR-RESULT-10).

### 12.3 구현이 어려운 부분

| 번호 | 부분 | 어려운 이유 | 줄이는 방법 |
| --- | --- | --- | --- |
| 1 | 지도의 표시, 목록, 아래 창의 선택 연동 (FR-MAP-03, 05, 14) | 표시와 카드와 창이 같은 아파트를 가리켜야 한다. | 선택한 아파트를 한곳에서 관리하고 세 곳이 그것만 읽게 한다. |
| 2 | 아래 창의 끌기와 스크롤 (FR-MAP-13, 17) | 창을 끄는 동작과 내용의 스크롤, 지도 끌기가 겹친다. | 1차에는 손잡이를 누르면 다음 단계로 바뀌게 한다. 끌기는 2차에 붙인다. |
| 3 | 창의 높이가 바뀔 때의 지도 | 지도 영역의 크기가 바뀌면 누른 아파트가 가려진다. | 창의 높이가 바뀔 때마다 남은 영역의 가운데로 지도를 다시 맞춘다. |
| 4 | 다시 계산했을 때의 갱신 (FR-RESULT-06) | 결과, 목록의 구분, 지도의 표시, 내 조건 줄이 함께 바뀐다. 요청이 세 번 나가서(시나리오, 아파트 찾기, 저축 계획 저장) 순서가 꼬이면 숫자가 서로 달라진다. | 시나리오의 응답을 받은 뒤 아파트 찾기를 부르고, 둘 다 성공하면 화면을 한 번에 바꾼다. 저축 계획 저장은 그 뒤에 부르고, 실패해도 화면을 되돌리지 않고 "저장하지 못했습니다"만 알린다. 검색 결과와 계산 결과는 한곳에 모아 두고 화면은 그것만 읽는다. |
| 5 | 표시가 많을 때 | 구 전체가 보이면 표시가 수백 개가 되어 겹치고 느려진다. | 넓게 보면 동 표시, 더 넓게 보면 구 표시로 바꾼다 (FR-MAP-20, 31). 바뀌는 확대 수준은 실제 지도를 보며 정한다. |
| 6 | 면적 슬라이더 (FR-APT-03) | 양쪽 끝을 움직이는 슬라이더는 기본 입력 요소에 없다. | 최소와 최대의 숫자 입력을 먼저 만들고 슬라이더는 나중에 붙인다. |
| 7 | 로그인 전후의 입력값 (FR-PROFILE-04) | 브라우저의 값과 DB의 값이 다를 수 있다. | "이어서 하기"는 DB의 값으로 채운다. 이전 버튼으로 돌아가면 값을 모두 남긴다. "처음부터 다시 입력"은 브라우저의 값을 모두 지우고, 재무정보 단계를 마칠 때 DB의 대출 선택과 저축 계획도 비운다. 세부 규칙은 `04_database_design.md` 3.2에 있다. |
| 8 | 광주 5개 구 경계 (FR-MAP-28) | 경계 좌표 자료가 필요하다. | 9.3의 방법을 쓴다. 자료를 구하지 못하면 경계 표시만 뒤로 미룬다. |
| 9 | 로드뷰 (FR-MAP-09, 10) | 로드뷰가 없는 위치가 있다. | 3차에 한다. 없는 곳은 기본 이미지로 바꾼다. |
