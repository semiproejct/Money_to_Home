## 1. 좌표 변환 스크립트

`data/geocode.py` (새 파일). 아파트의 주소를 카카오 API로 좌표로 바꿔 DB에 넣는다.

### 쓰는 API

카카오 로컬 API의 주소 검색이다.

| 항목 | 값 |
| --- | --- |
| 주소 | `https://dapi.kakao.com/v2/local/search/address.json` |
| 보내는 값 | `query` = 주소 |
| 머리말 | `Authorization: KakaoAK <REST API 키>` |
| 받는 값 | `documents[0]`의 `x`(경도), `y`(위도) |
| 키 | `.env`의 `KAKAO_REST_API_KEY`. **JavaScript 키가 아니다.** |

### 먼저 3 ~ 5건으로 시험한다

지역 이름이 2026년 7월에 바뀌었다. 어느 형식이 되는지 모른다. 전체를 돌리기 전에 몇 건으로 시험한다.

| 시험할 주소 | 예 |
| --- | --- |
| 새 이름 + 지번 | 전남광주통합특별시 서구 치평동 1171-4 |
| 옛 이름 + 지번 | 광주광역시 서구 치평동 1171-4 |
| 이름 없이 구부터 | 광주 서구 치평동 1171-4 |
| 도로명 | 전남광주통합특별시 서구 [도로명] |

- DB에는 `gu`, `dong`, `jibun`(지번), `road_address`(도로명. 구 이름 없이 "화산로 352"처럼 들어 있다)가 있다.
- 되는 형식을 찾으면 단체방에 알린다. 명세서의 남은 확인(R-06)이 풀린다.

### 넣는 곳

`apartments` 표의 세 칸이다.

| 칸 | 넣는 값 |
| --- | --- |
| `latitude` | 위도. 실패하면 비운다. |
| `longitude` | 경도. 실패하면 비운다. |
| `geocode_status` | `ok` 또는 `failed`. 비어 있으면 아직 변환하지 않은 것이다. |

### 규칙

- **이미 변환한 아파트는 다시 부르지 않는다.** `geocode_status`가 비어 있는 것만 부른다. `--force`를 주면 전부 다시 한다.
- 첫 형식으로 못 찾으면 다른 형식(도로명)으로 한 번 더 찾는다. 그래도 없으면 `failed`로 넣는다.
- 실패한 아파트를 화면에 출력하고 파일(`data/geocode_failed.csv`)로 남긴다.
- 호출 사이에 0.1초쯤 쉰다.
- 받은 좌표가 광주 5개 구 밖이면(위도 35.0 ~ 35.3, 경도 126.6 ~ 127.0을 벗어나면) 잘못 찾은 것이다. `failed`로 넣는다.
- `--dry-run`을 둔다. DB를 바꾸지 않고 몇 건을 부를지만 보여 준다.
- 키를 화면과 파일에 출력하지 않는다.
- DB 연결은 `backend.database.connect`를 쓴다. 본보기는 목산의 `data/load_trades.py`다. 한 번 돌리는 스크립트라 SQL을 직접 써도 된다. (서버 코드는 SQLAlchemy를 쓴다.)

### 돌리기 전에

**단체방에 알린다.** 약 1,055번을 부른다. 카카오의 하루 한도는 넷이 함께 쓴다. 한 번만 돌리면 된다.

### 좌표를 팀에 나누는 방법

좌표는 세환의 PC의 DB에만 들어간다. 나머지 세 명도 좌표가 필요하다. 넷이 각자 1,055번씩 부르지 않도록 **결과를 파일로 저장해 저장소에 올린다.**

| 파일 | 내용 |
| --- | --- |
| `data/geocoded.csv` | 구, 동, 지번, 아파트명, 위도, 경도, 결과 |

`geocode.py`에 `--from-file data/geocoded.csv`를 두어, 이 파일이 있으면 API를 부르지 않고 파일의 값을 DB에 넣게 한다. 나머지 세 명은 이 방법으로 넣는다.

### 화면의 구성 (모바일에는 헤더가 없다)

| 자리 | 내용 | 치수 |
| --- | --- | --- |
| 맨 위 | 내 조건 줄. "내 조건", 목표 가능 가격 문장, 수정, 로그인 | 높이 40 |
| 그 아래 | 검색 줄. 구·동 선택 버튼, 아파트 이름 검색창 | 위에서 49, 높이 32, 좌우 12 |
| 그 아래 | 조건 칩 줄. 면적, 가격, 준공 연도, 자금 부족 스위치 | 위에서 89, 높이 30 |
| 나머지 | 지도 | 내 조건 줄 아래 전체 |
| 오른쪽 아래 | ㎡/평, 현재 위치, 확대·축소 | 44 × 44, 오른쪽 12 |
| 왼쪽 아래 | 범례 (펼친 상태), 안내 아이콘 | 왼쪽 12, 아래 16 |
| 오른쪽 아래 | 목록 보기 | |

1차에 동작해야 하는 것은 내 조건 줄, 지도, 말풍선, 목록 보기, 아래 창이다. 검색, 칩, 범례, 지도 단추는 2차라서 모양만 두어도 된다.

### 맨 먼저 할 것

```js
if (!guard.requireInput()) return;   // 입력이 빠졌으면 그 단계로 보낸다
```

### 카카오맵 띄우기

키를 HTML에 적지 않는다. 서버에서 받아 온다.

```js
const { kakao_js_key } = await api.get('/api/config');
// 받은 키로 SDK를 불러온다. autoload=false로 불러 kakao.maps.load 안에서 지도를 만든다.
```

- 카카오 개발자 사이트에 `http://localhost:8000`이 등록되어 있다. 다른 포트로 열면 지도가 뜨지 않는다.
- **카카오 로고를 가리면 안 된다.** 로고는 기본으로 왼쪽 아래에 있는데 범례가 그 자리다. `map.setCopyrightPosition`으로 로고를 범례와 겹치지 않는 곳으로 옮긴다.
- 처음 위치와 확대 수준은 아직 정하지 않았다. 고른 구와 동이 있으면 그곳, 없으면 광주 5개 구의 가운데로 두고, 무엇으로 했는지 알린다.

### 다른 사람이 들어올 빈 자리

아래 창 안에 목록(목산)과 시나리오 탭(채은)이 들어온다. **틀과 빈 자리를 먼저 만들어 올리고, id를 단체방에 알린다.**

| 빈 자리 | 누가 채우는가 | 권하는 id |
| --- | --- | --- |
| 목록 | 목산 (`list.js`) | `sheet-list` |
| 아파트 정보 탭 | 세환 (`apartment.js`) | `sheet-apartment-info` |
| 시나리오 탭 | 채은 (`scenario.js`) | `sheet-scenario` |

`map.html`의 맨 아래에 세 사람의 스크립트를 불러오는 줄을 미리 넣어 둔다. 그러면 목산과 채은이 `map.html`을 고칠 일이 없다.

### 자료는 한곳에 둔다

고른 아파트와 면적은 `map-state.js` 한곳에만 둔다. 지도의 표시, 목록의 카드, 아래 창이 같은 아파트를 가리켜야 한다. 목산과 채은의 파일도 이 값을 읽는다. 값의 이름과 읽는 방법을 정해 알린다.

## 3. 말풍선 표시 (모양 A)

Figma 부품 "말풍선 (아파트 표시)"의 `모양=A 그라데이션`을 따른다. `모양=B 단색`은 쓰지 않는다.

| 항목 | 값 |
| --- | --- |
| 크기 | 72 × 57 (몸통 49 + 꼬리 8) |
| 위 줄 | 면적. 11px 굵게, 흰색 |
| 아래 줄 | 실거래 평균가 ("실 3.0억"). 16px 굵게, 흰색 |
| 바탕 | 위에서 아래로 진해지는 그라데이션 |
| 꼬리 | 왼쪽 아래. **꼬리의 끝(왼쪽에서 8.5)이 아파트의 좌표다.** |
| 누른 표시 | 1.2배 |
| 적지 않는 것 | "지금 +6.5천" 같은 여유·부족 금액. 누르면 아래 창에 나온다. |

색은 구분으로 정한다. 값은 Figma의 부품에서 읽는다.

| 구분 (`category`) | 색 |
| --- | --- |
| `now` 지금 가능 | 파랑 |
| `within` 기간 내 가능 | 라임 |
| `lack` 자금 부족 | 빨강 |

### 무엇을 적는가

A-05의 응답에서 아파트마다 `areas`의 **첫째 것**을 쓴다. 가장 싼 면적이다.

| 말풍선 | 응답의 값 |
| --- | --- |
| 면적 | `areas[0].supply_area`. 없으면(`null`) "전용 49㎡"처럼 `exclusive_area`. `format.area`를 참고한다. |
| 가격 | `areas[0].avg_price`를 "실 3.0억"으로 줄여 적는다. 줄이는 함수가 `format.js`에 없으면 팀장에게 말해 넣는다. |
| 색 | `apartments[].category` |

- **좌표가 `null`인 아파트는 그리지 않는다.** 목록에만 나온다.
- 꼬리의 끝이 좌표에 오도록 놓는다. 카카오맵의 `CustomOverlay`를 쓰면 `xAnchor`를 8.5 ÷ 72, `yAnchor`를 1로 둔다.
- 자금 부족 표시 스위치를 끄면 `lack`인 말풍선을 숨긴다. 서버를 다시 부르지 않는다.
- 아파트가 많아 겹칠 때의 처리는 아직 정하지 않았다. 먼저 그대로 그려 보고 얼마나 겹치는지 알린다.

### API가 아직 없을 때

목산의 A-05가 올라오기 전에는 명세서의 예시 응답을 코드에 임시로 적어 두고 만든다. 좌표는 자기 PC의 DB에서 몇 개 꺼내 쓴다. API가 올라오면 바꿔 끼운다.

## 4. 아래 창

| 단계 | 높이 | 열리는 때 |
| --- | --- | --- |
| 30% | 262 | 말풍선을 누름 |
| 80% | 지도 영역의 80% (390 × 844에서 643) | 목록 보기, 목록의 카드를 누름, 30%에서 손잡이를 올림 |
| 전체 | 내 조건 줄 바로 아래부터 | 80%에서 더 올림 |

- 80% 이상이면 검색 줄과 칩 줄을 숨긴다.
- 1차에는 손잡이를 누르면 다음 단계로 바뀌면 된다. 끌기는 2차다.
- 닫기 단추와 브라우저의 뒤로 가기로 닫는다.
- 30% 창에 보이는 것: 아파트명, 구분 배지, 이전·다음·닫기, 면적 고르기, "최근 1년 실거래 평균 3억 원", "5년 뒤 기준 여유 2,000만 원". 값은 A-05의 응답에 다 있다. 서버를 다시 부르지 않는다.

## 5. 아파트 한 곳 API (A-06)

`GET /api/apartments/{id}` — `backend/routers/apartment_detail.py`. 지금은 비어 있다.

- 목산의 `apartments.py`와 파일이 다르다. 서로 건드리지 않는다.
- **DB는 SQLAlchemy로 다룬다.** `models/`의 클래스(`Apartment`, `ApartmentPrice`)는 이미 있다. 만들지 않는다.
- DB를 읽는 함수는 `backend/services/apartment_detail.py`(새 파일)에, 응답의 모양은 `backend/schemas/apartment_detail.py`(새 파일)에 둔다. 본보기는 `services/profile.py`와 `routers/profile.py`다.
- 아파트 한 곳은 `db.get(Apartment, 번호)`로 읽고, 면적대별 평균가는 `apartment.prices`로 읽는다. 평균가가 낮은 순이다.
- 없는 번호면 404, "아파트를 찾을 수 없습니다."
- `households`(세대수)는 아직 없다. `null`로 준다.
- 응답의 모양은 API 명세서의 A-06을 그대로 따른다.

## 지킬 것

- 화면의 모양은 Figma "확정 목업 v3"을 따른다. Claude에 줄 때는 **화면 하나의 링크**를 준다.
- 색과 글자 크기는 `common.css`의 이름을 쓴다. 말풍선의 그라데이션처럼 거기 없는 값만 `map.css`에 둔다.
- 서버는 `api.get`, `api.post`로만 부른다. 저장소는 `store.get`, `store.set`으로만 읽고 쓴다.
- **계산식을 JavaScript에 쓰지 않는다.** 구분, 여유·부족 금액은 서버가 준 값을 보여 주기만 한다.
- 서버에서 온 글자는 `textContent`로 넣는다.
- 현재 위치는 브라우저 안에서만 쓴다. 저장하지 않고 서버로 보내지 않는다.
- 보이는 크기가 44보다 작은 것(검색 줄, 칩, 스위치, 목록 보기)은 누르는 영역만 44 이상으로 넓힌다.
