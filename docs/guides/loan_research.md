## 지킬 것

- **공식 안내 페이지에서만** 가져온다. 블로그와 기사는 쓰지 않는다.
- **금리가 범위로 나와 있으면** 대표로 쓸 값 하나를 정하고, 어떻게 정했는지 적는다. 예: "최저 금리", "범위의 가운데".
- **한도와 비율이 조건에 따라 다르면**(생애 최초, 지역 등) 가장 일반적인 조건의 값을 쓰고, 어떤 조건인지 자격 문구에 적는다.
- **값을 지어내지 않는다.** 못 찾은 칸은 비워 두고 팀장에게 알린다.
- 자격 조건은 **안내용**이다. 우리 서비스는 자격을 심사하지 않는다.
- 금액은 원 단위 정수로 적는다. "3억 6,000만 원"은 `360000000`이다.

### AI에게 시킬 때

대출 조건은 AI가 그럴듯하게 틀리기 쉽다.

1. "공식 페이지의 주소와 함께 값을 달라"고 한다.
2. **그 주소를 직접 열어 값이 맞는지 본다.** 확인하지 않은 값은 넣지 않는다.
3. 주소가 열리지 않거나 값이 다르면 그 값은 쓰지 않는다.

## 넣는 곳

`db/seed_loan_products.sql`의 두 줄을 고친다. 지금은 `[예시]`로 표시한 값이 들어 있다.

- 번호(`id`) 1과 2는 그대로 둔다. 다른 코드와 테스트가 이 번호를 쓴다.
- 파일 맨 위의 "아래 숫자는 전부 개발용 예시다"라는 주석을 "조사한 값이다. 기준일과 출처는 각 줄에 있다"로 고친다.
- 고친 뒤 HeidiSQL에서 파일을 열어 F9로 실행해 본다. 오류 없이 두 줄이 바뀌면 된다.

## 고치지 않는 것

**`tests/test_calc.py`의 숫자는 고치지 않는다.**

테스트는 계산식이 맞는지를 본다. 테스트 안에 예시 상품의 값(한도 3억 6,000만, 70%, 연 4.0%)이 따로 적혀 있어서, DB의 값이 바뀌어도 테스트는 그대로 통과해야 한다. 문서와 와이어프레임의 예시 숫자(최대 대출 116,666,666 등)도 그 예시 값으로 계산한 것이라 그대로 둔다.

## 다른 사람에게 주는 영향

없다. 조사가 끝나기 전까지는 모두가 지금의 예시 값으로 개발한다.

| 누가 | 예시 값으로 해도 되는가 |
| --- | --- |
| 목산의 아파트 찾기 API | 된다. DB에서 상품을 읽어 계산하므로 값이 바뀌면 결과만 달라진다. |
| 세환의 지도 | 된다. |
| 팀장의 입력 화면 | 대출과 무관하다. |

`seed_loan_products.sql`이 합쳐지면 각자 HeidiSQL에서 그 파일을 한 번 실행한다. 코드는 고칠 것이 없다.
