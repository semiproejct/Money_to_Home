# 최신 내용 받기 (2026-10-13)

오늘 `develop`에 규칙과 자료가 여러 번 바뀌었습니다. 아래 순서대로 한 번씩 실행해 주세요. 10분이면 끝납니다.

터미널은 VS Code의 터미널을 쓰고, 프로젝트 폴더(`C:\projects\Money_to_Home`)에서 실행합니다.

## 왜 해야 하나

- 각자의 Claude는 **내 컴퓨터의, 지금 작업 중인 브랜치에 있는 `CLAUDE.md`** 를 읽습니다. 받지 않으면 옛 규칙으로 일합니다.
- 대출 상품 값과 평균가 계산 방식이 바뀌어, DB도 한 번 다시 넣어야 합니다.

## 1. 하던 일을 먼저 저장한다

```bash
git status
```

- 바뀐 파일이 있는지 봅니다. 빨간 글씨로 파일이 나오면 저장하지 않은 작업이 있는 것입니다.
- 있으면 먼저 커밋합니다. 커밋하지 않고 다음 단계로 가면 합칠 때 막힐 수 있습니다.

```bash
git add 파일이름
```

```bash
git commit -m "feat: 하던 작업 내용"
```

- `git add .`은 쓰지 않습니다. 파일 이름을 적어 담습니다.

## 2. 깃허브의 최신 내용을 받아 온다

```bash
git fetch origin
```

- 깃허브에 있는 최신 내용을 내 컴퓨터로 가져오기만 합니다. 내 파일은 아직 바뀌지 않습니다.

## 3. 내 작업 브랜치에 최신 develop을 합친다

```bash
git merge origin/develop
```

- 지금 있는 브랜치에 최신 `develop`을 합칩니다. 이 단계에서 `CLAUDE.md`와 문서, 다른 사람이 만든 코드가 들어옵니다.
- `develop`을 받기만 하고 이 단계를 빼먹으면, 작업 브랜치의 `CLAUDE.md`는 옛것 그대로입니다.
- `CONFLICT`라는 글자가 나오면 멈추고 팀장에게 알려 주세요. 혼자 풀지 않아도 됩니다.

## 4. 제대로 받았는지 확인한다

```bash
git log -1 --format="%h %s" -- CLAUDE.md
```

- `CLAUDE.md`를 마지막으로 고친 커밋이 나옵니다.
- 아래 둘 중 하나가 나오면 최신입니다.
  - `d8e869f docs: 검증하고 결과를 보여 주는 방법을 CLAUDE.md에 추가`
  - `026f5c6 docs: 수집 기간을 수집 스크립트에 맞춰 12개월로 되돌림` (검증 방법 PR이 아직 머지되지 않았을 때)
- 다른 것이 나오면 2번과 3번을 다시 합니다.

## 5. DB를 다시 넣는다

- 여러 번 실행해도 됩니다.

**평균가** — 가상 환경을 켠 뒤 실행합니다.
