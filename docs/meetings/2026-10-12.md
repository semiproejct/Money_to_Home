### 2.3 분담안 (제안)

| 역할 | 맡는 것 | 1차 작업 | 맞는 사람 | **담당자** |
| --- | --- | --- | --- | --- |
| A. 입력 화면 | 재무정보, 저축 계획, 시작 화면, 공통 화면 틀. 2차에 회원 기능 | 약 15개 | 화면 만들기를 좋아하는 사람 | |
| B. 대출과 계산 | 대출 상품 조사, 대출상품 화면, 계산 모듈 전체와 테스트, 시나리오 API | 약 14개 | 숫자와 공식에 꼼꼼한 사람 | |
| C. 데이터와 탐색 | 실거래 수집과 적재, 좌표 변환, DB, 아파트 찾기 API, 목록 화면 | 약 17개 | 파이썬과 Pandas에 익숙한 사람 | |
| D. 지도와 아래 창 | 카카오맵, 아파트 표시, 아래 창, 아파트 정보 탭, 시나리오 화면 | 약 16개 | JavaScript에 가장 익숙한 사람 | |

- 계산 모듈은 한 사람(B)이 맡는다. API 여섯 개가 이 모듈에 기대므로 가장 먼저 끝나야 한다.
- 팀장은 Git 관리, PR 승인, 문서 관리, 통합 점검을 함께 한다. 일이 가장 많은 D는 피하는 것이 좋다.
- 역할별로 맡는 파일은 `docs/06_architecture.md` 9.3에 있다.

### 4.2 각자 할 일

1. 저장소를 내려받는다: `git clone https://github.com/semiproejct/Money_to_Home.git`
2. HeidiSQL에서 `db/schema.sql`을 열어 F9로 실행한다. 표 8개가 생긴다.
3. `.env.example`을 복사해 `.env`를 만든다. DB 계정은 각자 것을, API 키는 팀장이 준 값을 넣는다.
4. `docs/00_summary.md`를 읽는다.

### 4.3 팀장이 따로 전달할 것

- API 키 3개 (공공데이터, 카카오 JavaScript, 카카오 REST). 개인 메시지로 전한다. Git과 단체방에는 올리지 않는다.
- 카카오맵은 팀장의 앱 하나를 넷이 함께 쓴다.

## 5. 함께 지킬 규칙

| 규칙 | 이유 | 동의 |
| --- | --- | --- |
| 계산식은 계산 모듈에만 둔다. | 화면마다 숫자가 달라지는 것을 막는다. | |
| 각자 자기 파일만 고친다. 공통 파일은 만든 사람에게 말한다. | 합칠 때 충돌이 줄어든다. | |
| API의 모양은 API 명세서를 따른다. 바꾸려면 명세서를 먼저 고친다. | 화면과 서버가 따로 만들어도 맞물린다. | |
| 금액은 원 단위 정수로 주고받는다. | 만원과 원이 섞이면 10,000배 틀린다. | |
| 키와 비밀번호는 `.env`에만 둔다. | Git에 올라가면 공개된다. | |
| `main`과 `develop`에 직접 올리지 않는다. 작업 브랜치에서 PR을 보낸다. | README의 협업 규칙 | |
| 커밋 메시지는 `종류: 내용` 형식으로 쓴다. 예: `feat: 대출 계산 API 추가` | README의 협업 규칙 | |
