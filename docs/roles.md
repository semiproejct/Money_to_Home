# 역할 분담

| 항목 | 내용 |
| --- | --- |
| 정한 날 | 2026-10-12 |
| 상태 | 확정 |
| 원칙 | 네 명 모두 화면(HTML, CSS, JavaScript), 서버(Python), DB를 다 쓴다. 기능 하나를 화면부터 DB까지 한 사람이 맡는다. |

## 1. 큰 역할

| 담당 | 맡는 기능 | 한 줄 설명 |
| --- | --- | --- |
| 김해원 (팀장) | 입력과 공통 | 사용자가 자기 정보를 넣는 화면, 모두가 쓰는 틀 |
| 박채은 | 대출과 계산 | 대출 상품을 고르고, 얼마가 필요한지 계산해 보여 준다. |
| 김목산 | 자료와 탐색 | 실거래 자료를 넣고, 조건에 맞는 아파트를 찾아 목록으로 보여 준다. |
| 안세환 | 지도와 아파트 창 | 지도에 아파트를 표시하고, 누르면 정보를 보여 준다. |

사용자가 서비스를 쓰는 순서와 같다.

```
입력(해원) → 대출(채은) → 지도(세환) → 목록(목산) → 결과(채은)
```

## 2. 사람별로 쓰는 기술

| 담당 | 화면 (HTML, CSS, JS) | 서버 (Python) | DB |
| --- | --- | --- | --- |
| 김해원 | 시작, 재무정보, 저축 계획 | 재무정보 저장, 저축 계산 | `users`, `profiles` |
| 박채은 | 대출상품, 시나리오 탭 | 계산 모듈, 대출 계산, 시나리오 | `loan_products` |
| 김목산 | 목록, 카드, 조건과 정렬 | 적재 스크립트, 아파트 찾기 | `apartments`, `trades`, `apartment_prices` |
| 안세환 | 지도, 아파트 표시, 아래 창, 아파트 정보 탭 | 좌표 변환, 아파트 한 곳 조회 | `apartments`의 좌표 |

## 4. 서로 기다리는 지점

| 먼저 | 그다음 | 이유 |
| --- | --- | --- |
| 채은 1 (계산 모듈) | 목산 4 (아파트 찾기) | 구분을 계산 함수로 매긴다. |
| 목산 2 (적재) | 세환 2 (좌표 변환) | 아파트가 DB에 있어야 좌표를 붙인다. |
| 세환 2 (좌표) | 세환 4 (아파트 표시) | 좌표가 없으면 지도에 찍을 수 없다. |
| 해원 1 (색, 부품) | 모두의 화면 작업 | 모양이 정해져야 화면을 만든다. |

## 6. 지도 화면은 세 명이 함께 쓴다

`map.html` 하나에 지도와 아래 창(세환), 목록(목산), 시나리오 탭(채은)이 들어온다. 세환이 틀과 빈 자리를 먼저 만들고, 나머지는 각자 파일에서 작업한다.

| 파일 | 담당 |
| --- | --- |
| `map.html`, `map-view.js`, `sheet.js`, `apartment.js` | 안세환 |
| `list.js`, `list.css` | 김목산 |
| `scenario.js`, `scenario.css` | 박채은 |

## 7. 지킬 것

- 자기 담당 파일만 고친다. 남의 파일을 고쳐야 하면 담당에게 먼저 말한다.
- `backend/main.py`에는 새 router를 등록하는 한 줄만 더한다.
- 계산식은 `backend/services/calc.py`에만 둔다. 화면과 router에 쓰지 않는다.
- 카카오 API를 많이 부르는 스크립트(좌표 변환)는 돌리기 전에 단체방에 알린다.
- 스크립트로 DB를 채우면 자기 PC에만 들어간다. 스크립트가 `develop`에 합쳐지면 나머지도 각자 한 번 돌린다.
