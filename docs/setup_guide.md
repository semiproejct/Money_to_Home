# 개발 환경 맞추기 (처음 하는 사람용)

| 항목 | 내용 |
| --- | --- |
| 대상 | 프로젝트를 처음 해 보는 팀원 |
| 걸리는 시간 | 프로그램이 이미 깔려 있으면 20분, 새로 깔면 1시간 |
| 목표 | 네 명의 PC에 같은 폴더, 같은 프로그램, 같은 DB가 있는 상태 |
| 막히면 | 화면을 캡처해서 팀장에게 보낸다. 혼자 오래 붙잡지 않는다. |

**순서대로 따라 한다. 건너뛰지 않는다.** 각 단계 끝에 "확인"이 있다. 확인이 안 되면 다음으로 넘어가지 않는다.

## 전체 순서

1. 폴더 만들기
2. 프로그램 확인 (Git, Python, MariaDB, VS Code). 없는 것만 설치
3. 프로젝트 내려받기
4. DB 만들기
5. `.env` 파일 만들기
6. 마지막 확인
7. 라이브러리 설치와 서버 실행

---

## 0. 먼저 알아 둘 말

| 말 | 뜻 |
| --- | --- |
| 폴더, 경로 | 폴더는 파일을 담는 곳이고, 경로는 그 폴더의 주소다. 예: `C:\projects\Money_to_Home` |
| 터미널 | 글자로 명령을 내리는 창. 이 문서에서는 VS Code 안의 터미널을 쓴다. |
| 명령 | 터미널에 한 줄 적고 Enter를 누르는 것 |
| 저장소 | 프로젝트 파일이 모여 있는 곳. GitHub에 있는 것을 내 PC로 내려받는다. |
| 브랜치 | 저장소의 작업 갈래. 기준은 `develop`이다. |
| DB | 자료를 표로 보관하는 프로그램. MariaDB를 쓴다. |

## 1. 폴더 만들기

네 명이 **똑같은 경로**를 쓴다. 경로가 같아야 서로 화면을 보며 도울 수 있다.

1. 파일 탐색기를 연다 (키보드의 `Windows` + `E`).
2. 왼쪽에서 **내 PC**를 누르고 **로컬 디스크 (C:)** 를 연다.
3. 빈 곳을 오른쪽 버튼으로 누르고 **새로 만들기 > 폴더**를 고른다.
4. 이름을 `projects`로 적는다.

지켜야 할 것

- 폴더 이름에 **한글과 띄어쓰기를 쓰지 않는다.** 일부 프로그램이 한글 경로에서 오류를 낸다.
- 바탕화면, 문서, OneDrive 안에 만들지 않는다. 자동으로 올라가는 폴더라 파일이 꼬일 수 있다.

**확인**: 탐색기의 주소 칸에 `C:\projects`가 보인다.

## 2. 프로그램 확인

Python, MariaDB, VS Code는 수업에서 이미 설치했다. **다시 설치하지 않고 버전만 확인한다.** 버전이 다르거나 없는 것만 2.1 ~ 2.4를 보고 설치한다.

### 버전 확인

1. VS Code를 연다.
2. 위쪽 메뉴에서 **터미널 > 새 터미널**을 누른다. 아래에 글자를 적는 창이 열린다.
3. 아래를 한 줄씩 적고 Enter를 누른다.

```
python --version
```

```
git --version
```

4. HeidiSQL을 열어 DB에 접속한 뒤, 위쪽의 **쿼리** 탭에 아래를 적고 F9를 누른다.

```
SELECT VERSION();
```

| 프로그램 | 나와야 하는 것 | 다르면 |
| --- | --- | --- |
| Python | `Python 3.12.`로 시작 | 3.11이나 3.13이면 팀장에게 알린다. 대부분 그대로 써도 되지만 넷이 같은 편이 안전하다. |
| Git | `git version 2.`로 시작 | "찾을 수 없습니다"가 나오면 2.1을 보고 설치한다. |
| MariaDB | `11.4.`로 시작하고 `MariaDB`가 붙음 | `8.0`처럼 MySQL이 나오거나 버전이 다르면 **팀장에게 먼저 알린다.** 지우거나 새로 깔지 않는다. |

**확인**: 세 가지가 표와 같다. 결과를 회의록의 표에 적는다.

아래 2.1 ~ 2.4는 프로그램이 없을 때만 본다. 모두 있으면 3장으로 넘어간다.

### 2.1 Git

파일의 변경 기록을 남기고 팀과 주고받는 프로그램이다.

1. https://git-scm.com/downloads 에서 Windows용을 내려받아 실행한다.
2. 끝까지 **Next**를 누르고 **Install**을 누른다.

### 2.2 Python 3.12

1. https://www.python.org/downloads/ 에서 **3.12**로 시작하는 버전을 내려받아 실행한다. 맨 위의 최신 버전이 3.12가 아니면 아래 목록에서 3.12를 찾는다.
2. **첫 화면 아래쪽의 "Add python.exe to PATH"를 반드시 체크한다.** 이것을 빼먹으면 터미널이 Python을 찾지 못한다.
3. **Install Now**를 누른다.

### 2.3 MariaDB 11.4

1. https://mariadb.org/download/ 에서 버전을 **11.4**로 고르고 Windows용 MSI 파일을 내려받아 실행한다.
2. 설치 중에 **root 비밀번호**를 묻는다. 정한 비밀번호를 **메모장에 적어 둔다.** 잊으면 다시 설치해야 한다.
3. "Use UTF8 as default server's character set"이 보이면 체크한다.
4. HeidiSQL을 함께 설치할지 묻는 항목은 그대로 둔다 (함께 설치된다).
5. 나머지는 **Next**를 누른다.

### 2.4 VS Code

코드를 보고 고치는 편집기다.

1. https://code.visualstudio.com/ 에서 내려받아 실행한다.
2. 끝까지 **다음**을 누른다.

설치한 뒤에는 위의 "버전 확인"을 다시 한다. 터미널이 프로그램을 찾지 못하면 VS Code를 껐다 켠다.

## 4. DB 만들기

1. 시작 메뉴에서 **HeidiSQL**을 찾아 연다.
2. 왼쪽 아래의 **신규**를 누른다.
3. 오른쪽에 아래처럼 적는다.

| 칸 | 값 |
| --- | --- |
| 호스트명 / IP | `127.0.0.1` |
| 사용자 | `root` |
| 암호 | MariaDB를 설치할 때 정한 root 비밀번호 |
| 포트 | `3306` |

4. **열기**를 누른다. 저장할지 물으면 **예**를 누른다.
5. 위쪽 메뉴에서 **파일 > SQL 파일 불러오기**를 누르고 `C:\projects\Money_to_Home\db\schema.sql`을 고른다.
6. 키보드의 **F9**를 누른다. 실행하는 단추다.
7. 왼쪽 목록을 오른쪽 버튼으로 누르고 **새로 고침**을 누른다.

**확인**: 왼쪽에 `money_to_home`이 생기고, 펼치면 표 8개가 보인다.

```
apartment_prices, apartments, data_collections, loan_products,
profiles, saved_results, trades, users
```

표를 누르면 칸마다 한글 설명이 보인다. 실수로 여러 번 실행해도 괜찮다. 이미 있는 표는 건너뛴다.

## 5. `.env` 파일 만들기

키와 비밀번호를 적어 두는 파일이다. **이 파일은 Git에 올라가지 않는다.** 각자 자기 PC에 만든다.

1. VS Code 왼쪽에서 `.env.example`을 오른쪽 버튼으로 누르고 **복사**를 누른다.
2. 왼쪽 빈 곳을 오른쪽 버튼으로 누르고 **붙여넣기**를 누른다. `.env copy.example` 같은 이름으로 생긴다.
3. 그 파일을 오른쪽 버튼으로 누르고 **이름 바꾸기**를 눌러 `.env`로 고친다. 앞에 점이 있고 뒤에 아무것도 붙지 않는다.
4. `.env`를 열어 `=` 뒤에 값을 적는다. **따옴표와 띄어쓰기 없이** 붙여 적는다.

| 이름 | 적을 값 |
| --- | --- |
| `DATA_GO_KR_KEY` | 팀장이 준 값 |
| `KAKAO_JS_KEY` | 팀장이 준 값 |
| `KAKAO_REST_API_KEY` | 팀장이 준 값 |
| `DB_HOST`, `DB_PORT`, `DB_NAME` | 고치지 않는다. |
| `DB_USER` | `root` |
| `DB_PASSWORD` | MariaDB를 설치할 때 정한 root 비밀번호 |
| `SESSION_SECRET_KEY` | 비워 둔다. |

5. `Ctrl` + `S`로 저장한다.

절대 하면 안 되는 것

- 키와 비밀번호를 **`.env.example`에 적지 않는다.** 그 파일은 Git에 올라간다.
- 키를 단체방, 캡처, GitHub에 올리지 않는다.

**확인**: 터미널에 아래를 적는다.

```
git status
```

결과에 `.env`가 **보이지 않으면** 맞다. `.env`가 목록에 보이면 팀장에게 알린다.

## 7. 라이브러리 설치와 서버 실행

VS Code의 터미널에서 한다. 터미널의 경로가 `C:\projects\Money_to_Home`인지 먼저 본다.

### 7.1 최신 내용 받기

```
git checkout develop
```

```
git pull
```

왼쪽에 `backend`, `frontend`, `tests` 폴더가 보이면 맞다.

### 7.2 가상 환경 만들기 (처음 한 번)

가상 환경은 이 프로젝트만 쓰는 Python 방이다. PC에 깔린 다른 Python이나 다른 수업의 라이브러리와 섞이지 않는다.

```
python -m venv .venv
```

프로젝트 폴더에 `.venv` 폴더가 생긴다. 이 폴더는 Git에 올라가지 않는다.

### 7.3 가상 환경 켜기 (터미널을 열 때마다)

```
.venv\Scripts\activate
```

터미널 줄의 맨 앞에 `(.venv)`가 붙으면 켜진 것이다. **이 표시가 없으면 아래 명령을 실행하지 않는다.**

"이 시스템에서 스크립트를 실행할 수 없으므로"라는 빨간 글자가 나오면, 터미널 오른쪽 위의 `+` 옆 화살표를 눌러 **Command Prompt**를 고르고 다시 한다.

### 7.4 라이브러리 설치 (처음 한 번, 그리고 `requirements.txt`가 바뀌었을 때)

```
pip install -r requirements.txt
```

2 ~ 3분 걸린다. 마지막에 `Successfully installed`가 나오면 맞다.

`requirements.txt`가 바뀌었다는 알림을 받으면 이 명령을 다시 실행한다. 이미 깔린 것은 건너뛰고 새것만 깐다. 서버를 켰을 때 `ModuleNotFoundError`가 나오면 이 명령을 안 한 것이다.

### 7.5 대출 상품 자료 넣기

HeidiSQL에서 **파일 > SQL 파일 불러오기**로 `C:\projects\Money_to_Home\db\seed_loan_products.sql`을 열고 **F9**를 누른다. `loan_products` 표에 두 줄이 생긴다. 보금자리론과 카카오뱅크 주택담보대출의 실제 조건이다. 이 파일이 바뀌면 `git pull` 한 뒤에 한 번 더 실행한다. 여러 번 실행해도 된다.

### 7.6 실거래 자료와 좌표 넣기

가상 환경을 켠 터미널에서 차례로 실행한다. 외부 API를 부르지 않고 저장소에 든 파일에서 넣는다. 여러 번 실행해도 된다.

```
python data/load_trades.py data/collected
python data/load_supply_area.py
python data/geocode.py --from-file data/geocoded.csv
```

- 첫째 줄은 아파트와 거래, 면적대별 평균가를 넣는다. 끝에 "아파트 1,055곳"이 나온다.
- 둘째 줄은 공급면적을 붙인다.
- 셋째 줄은 좌표를 넣는다. "파일에서 넣음 1,055곳"이 나온다. 좌표가 없으면 지도에 아파트가 나오지 않는다.

### 7.7 서버 켜기

```
uvicorn backend.main:app --reload --port 8000
```

`Application startup complete.`가 나오면 켜진 것이다. 이 터미널은 서버가 쓰고 있으므로 그대로 둔다. 끄려면 `Ctrl` + `C`를 누른다.

**확인**: 브라우저에서 아래 세 주소를 연다.

| 주소 | 보여야 하는 것 |
| --- | --- |
| http://localhost:8000 | 시작 화면 |
| http://localhost:8000/api/health | `{"status":"ok","db":"ok"}` |
| http://localhost:8000/docs | API 목록 |

`"db":"error"`가 나오면 `.env`의 `DB_USER`와 `DB_PASSWORD`를 다시 본다. 고친 뒤에는 서버를 껐다 켠다.

### 7.8 자동 테스트 돌리기

서버를 켠 터미널 말고 새 터미널을 열어 7.3을 한 뒤 실행한다.

```
pytest
```

`passed`가 나오고 `failed`가 없으면 맞다.

### 다음부터는

터미널을 열 때마다 7.3(가상 환경 켜기)과 7.6(서버 켜기)만 하면 된다.

| `python`을 찾을 수 없다고 나온다. | 설치할 때 "Add python.exe to PATH"를 체크하지 않았다. Python을 지우고 다시 설치한다. |

| 3306 포트를 쓸 수 없다고 나온다. | 다른 DB(MySQL 등)가 이미 깔려 있다. 팀장에게 알린다. |
| `.env`의 이름이 `.env.txt`가 된다. | 메모장으로 만들면 그렇게 된다. VS Code에서 만든다. |
| 터미널의 경로가 다르다. | `cd C:\projects\Money_to_Home`을 다시 적는다. |

## 하지 말아야 할 것

- 폴더 이름과 파일 이름을 바꾸지 않는다. 다른 사람의 코드가 그 이름을 쓴다.
- 표를 HeidiSQL에서 손으로 만들거나 고치지 않는다. `db/schema.sql`로만 만든다.
- `main`과 `develop` 브랜치에 직접 올리지 않는다.
- 모르는 명령을 인터넷에서 찾아 그대로 실행하지 않는다. 먼저 팀장에게 묻는다.
